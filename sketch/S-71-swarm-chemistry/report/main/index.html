何をやったか

題材

Sayama の Swarm Chemistry の再実装である。各粒子は「型」を持たない。持っているのは 8 つ組ゲノム（知覚半径 R・通常速度 Vn・最大速度 Vm・凝集 c1・整列 c2・分離 c3・乱択操舵確率 c4・速度維持 c5）だけで、粒子は近傍集合の集約（重心・平均速度・分離力の和）にしか反応しない。S-46（Particle Life）が持っていた型ペアの相互作用行列 G[a][b] はどこにも無い。これが本スケッチの問いの前提である: 相手を名指しできない系に、非相反な追跡/被追跡関係は出るか。

場は 500 × 500、N = 200（レシピの行ごとの個体数比を保って最大剰余法で丸める。丸めで 0 個体になった行は 19 本を通して1つも出なかった——capped/rescaled-recipes.json の dropped は全レシピで空）。バーンイン 400 + 測定窓 800 ステップ、10 ステップごとに 80 時点抽出。腕は 9 本（A1 登録どおり／A2 R 共通化／A3 力の強さ共通化／A4 移植の壁反発／A5 近傍応答ゼロ／A6 単一ゲノム／A7 一様ランダム 0 ステップ／A8 1点密集／A9 構成した追跡ペア）、シードは 3 つ。

観測器（S-02・S-13 から定義を変えずに借りた2本 + 本スケッチ固有の3本）

  • OP1 excessNeighborRatio（S-02 から。閾値 1.5、帰無値 1.0）— 粒子 i の近傍数を一様場の期待値 (N−1)·A_eff(R,x_i)/L² で割る。半径は観測者が選ばず粒子自身の R を使う。R > 150 のゲノム行は対象外（上限）
  • OP2 genomeSegregationIndex（閾値 1.3、帰無値 1.0）— r_seg = 50 内の近傍ペアのうち同ゲノムの割合を、ラベル入替え帰無 199 回の平均で割る
  • OP3 pursuitAsymmetryIndex（主判定量。閾値 0.25、定義域 [0,2]、雑音床 0.08）— 相異なるゲノム行の無順序ペア {a,b} について ΔC = |C(b→a) − C(a→b)| のペア平均
  • OP4 perceptionAttributionRho（閾値 0.5）— レシピの知覚半径非対称度 A(r) と OP3 の Spearman 順位相関。1標本 = 1レシピで他の OP と階層が違う
  • OP5 spatialScaleCount（S-13 から。閾値 2、帰無値 0）— L(r)−r が CSR 包絡（99本・点ごと 2.5–97.5%）の外に出る連結な区間の本数、r ∈ [5,250]

結果（事前登録した解析）

① 459 標本が走ったか — 走った。ただし独立な初期配置は 3 つしかない

replicates.jsonl は 459 行（A1〜A8 が各 57 = 19 レシピ × 3 シード、A9 が 3）で、腕の欠けは無い。予測表 18 マスに空白は無い。

シードの効き方: A1 の 57 標本は stateHash が 57 通りすべて相異なる（whatSeedChanges が要求した「3 シードの生ログが互いに異なる」は満たされている）。全行 c4 = 0 のレシピは 19 本中 0 本（prior/seed-sensitivity-precheck.json の anyFullyZero: false）で、K-47 型の「シードが何も変えない」は起きていない。

ただし初期配置そのものはシードだけで決まる。 core.js:282-298 の初期位置は deriveSeed(seed,'init-pos') から 200 粒子分を行順に引くだけで、レシピにも腕にも依存しない。したがって A1〜A7・A9 は、同じシードなら 19 レシピすべてが同一の 200 点から出発している。力学を回す腕では軌道が分かれるので実害は小さいが、力学を回さない A7（0 ステップ）では 57 標本の stateHash が 3 通りしか無い——A7 の「57 標本」は、独立な帰無の実現としては 3 つである。これは §5 の A7 の読み方を変える。

② 主判定 — 機械判定は「支持されなかった」。3条件の内訳を開くと、落ちたのは1つだけ

decisionRule は「(a)(b)(c) が全て成り立つときに限り主張してよい」と書く。summary.json の decision はこうなっている:

条件登録した基準summary.json の記録生ログから数え直した値
(a)A1 で OP3 が 0.25 超のレシピが 19 本中 5 本以上、各レシピで 3 シード中 2 つ以上positiveRecipes: 0 → 偽15 本 → 真
(b)A5 で 0.25 超のレシピが 2 本以下、かつ A5 の OP3 中央値が 0.08 未満positiveRecipes: 0／median: 0.10857 → 偽0 本（真）／0.1086（偽）
(c)A9（構成した追跡ペア）で OP3 が 0.25 超[0.677, 0.570, 0.626] → 真同じ → 真

条件(a) の 0 は数字ではない。 run.js:36 は閾値表を

CRIT.orderParameters.forEach((o) => { THRESHOLDS[o.name] = o.threshold; });

で作るので、鍵は excessNeighborRatio / genomeSegregationIndex / pursuitAsymmetryIndex / perceptionAttributionRho / spatialScaleCount の5つになる。ところが run.js:245-248 の

function isPositive(name, value) {
  if (value == null || isNaN(value)) return false;
  return value >= THRESHOLDS[name];
}

は recipePositiveCount(armId, opName)（run.js:251-265）から opName = 'op1'〜'op5' で呼ばれる。THRESHOLDS['op3'] は undefined であり、0.677 >= undefined は false である。したがって isPositive は入力によらず常に偽を返す。 実際に走らせて確かめた（999 >= THRESHOLDS['op3'] も false）。

この関数が決めているのは:

  • 規則B（効くか）の 36 マス全部（4 観測器 × 9 腕）。だから summary.json の ruleB_positiveRecipes は 45 マスすべてで 0、ruleB_pass は 45 マスすべてで false になっている
  • 条件(a)（run.js:305,310）— どんな走行結果でも偽
  • 条件(b) の前半（run.js:306,311 の a5Recipe.positiveRecipes <= 2）— どんな走行結果でも真（空虚に）

条件(c)（run.js:312）だけは THRESHOLDS.pursuitAsymmetryIndex を直接読んでいるので正しく効いている。OP4 の ruleB_pass（run.js:299）も同様に正しい鍵を使っている。つまり壊れているのは isPositive() 経由の経路だけで、それがちょうど規則Bと条件(a)(b)前半である。

これは criteria.json に登録されていない量で結論が決まっている形（K-60）であり、S-53 が見つけた「登録した条件式の分母が 0 になり、実装が criteria に無い代替規則へ切り替えた」件と同じ型である。 ただし向きが違う: S-53 は代替規則が判定を通したが、ここでは参照名の食い違いが判定を通さなかった。

結論への影響: 登録どおりに (a)(b)(c) を評価すると (a)=真・(b)=偽・(c)=真 であり、claimSupported は依然として偽である。「主張は支持されなかった」という結論は変わらない。変わるのは、この走行が何を見たかである——走行側の記録を字義どおりに読むと「A1 で非相反は1本も出ていない」になるが、実際には 19 本中 15 本で出ていた。

③ 実データで落ちた唯一の条件(b) — 0.1086 は何であるか

A5（c1 = c2 = c3 = 0。粒子は互いに独立なランダムウォークになる）の OP3 中央値は 0.1086 で、雑音床 0.08 を上回る。レシピ別に見ると 0.0769（Playing Catch）〜0.1550（Slicer）で、A5 の 17 本すべてが登録閾値 0.25 を下回っている（陽性 0 本）。したがって A5 は「相互作用が無いのに追跡が見える」ほどではないが、「登録した雑音床より上」ではある。

S2 の申し送り §3 は原因を「R・Vn・Vm がゲノム間で異なることによる運動学的異質性」と特定したと書いている。この申し送りは裏が取れなかった。 3つの理由を挙げる。

第一に、selftest §6 の「速度を等方一様にランダムに与える」検査が 0.1121 を返している。 この検査では全粒子に同じ速さ 5 の等方一様な向きを与えており（selftest.js:143-146）、位置は一様、力学は 0 ステップである。R も Vn も Vm も測定には一切入らない。それでも 0.08 を 40% 上回る。

第二に、A5 の値はゲノム行あたりの個体数だけで当てられる。 1時点の |ΔC| の期待値は、各有向量 C が N_g 個の粒子にわたる cos の平均（cos の標準偏差は等方なら 1/√2）であることから、当てはめパラメータ無しに

E|ΔC(a,b)| = √(2/π) · (1/√2) · √(1/n_a + 1/n_b)

と書ける。これをレシピ内の全ペアで平均した値と、A5 の実測 OP3（3 シード平均）を 17 レシピで比べると Pearson r = 0.992、比は 0.942〜1.058（中央値 0.989・平均 0.993）である。

第三に、S2 が「均質なら床へ戻る」根拠にした selftest §7 の数値が、同じ式で説明できる。 その検査は 2 ゲノム × 100 個体で作られており、上式は 0.0798 を与える（実測 0.0815）。すなわち 0.08 へ戻ったのは 8 パラメータを揃えたからではなく、1 行あたり 100 個体にしたからである。 同じ 100/100 の構成なら R・Vn・Vm がばらついていても 0.08 前後になるはずで、実際 A5 で最も低いのは 2 行構成の Playing Catch（0.0769）・Turbulent Runner（0.0807）・Recombining Blobs（0.0794）——いずれも行あたり個体数が大きいレシピである。逆に最も高い Slicer（0.1550）は 12:1 を 200 へ丸めた 185:15 の構成で、少ないほうの行が床を押し上げている。

（上式の導出と当てはめは事前登録に無い。§「事後解析」で扱う。この節で事前登録に基づいて言えるのは、「条件(b) は A5 の実測中央値 0.1086 が雑音床 0.08 を上回ったために落ちた」という事実までである。）

④ 主判定量そのものが、登録された量と違う

なぜ床が 0.08 でなく 0.11 なのか。criteria.json の OP3 の定義文はこう書いている（強調は本レポート）:

各時点・各 b 粒子 i について……cos θ = u_ij · v̂_i を取り、b 粒子と時点にわたって平均する。……非相反度を ΔC(a,b) = |C(b→a) − C(a→b)| と定め、レシピ内の全無順序ペアにわたる平均を指標とする。

すなわち C(b→a) は粒子と時点の両方で平均してから、絶対差を取る。noiseFloor.howEstimated はこの読みとだけ整合する——「ゲノム行あたりの個体数 N_g ≈ 33 と……実効独立時点数 20 の積 33 × 20 = 660。したがって C(b→a) の標準誤差は 0.707/√660 ≈ 0.028」。時点で平均することが √20 の縮小を生む前提で 0.08 が出ている。

実装はそうなっていない。run.js:144 は各サンプル時点で pursuitAsymmetryAtInstant(world) を呼び、stats.js:247 がその時点の中で絶対値を取る:

deltas.push(Math.abs(cBA.sum / cBA.cnt - cAB.sum / cAB.cnt));

そして stats.js:259（pursuitAsymmetryOverWindow）が、その絶対値たちを時間平均する。絶対値が先に入るので時間平均は 0 へ向かわず、E|ΔC_時点| ≈ √(2/π)·0.707·√(1/n_a+1/n_b) へ収束する。N_g = 33 なら 0.139、N_g = 100 なら 0.080。登録の 660 ではなく 33 の床が立っている。

sampleUnit の側には「1標本の代表値は……80 時点抽出し、その時間平均」という記述もあり、実装はこちらの読みを採ったと解せる。だが noiseFloor の導出はもう一方の読みでしか成立しない。 登録の内部に2通りの読みがあり、実装が片方を採った結果、雑音床だけがもう片方の読みのまま残った。

この食い違いは書き換えない。書く。——(ⅰ) 主判定量 OP3 の実測値は、定義文どおりの量ではない。(ⅱ) 条件(b) が落ちたのは、A5 に構造があるからではなく、登録された雑音床が、実装された推定量の床ではないからである。(ⅲ) 生ログには時点ごとの C(b→a) が残っていない（replicates.jsonl は窓平均済みの op3 だけ）ので、定義文どおりの OP3 を本レポートから再構成することはできない。それには再走行が要り、それは S4 の仕事ではない。

⑤ 対照の点検 — 4つのうち2つが、登録した検算を実行できていない

(1) OP3 のゼロ速度除外 20% — 除外割合が 20% を超えた標本は Multicellularity の 0.205 ちょうどのみ。内訳は core.js の Multicellularity 第2行 48 * (300.0, 14.63, 0.0, …)——最大速度 Vm = 0 のゲノム行で、200 へ丸めて 41 個体、41/200 = 0.205 である。上限 0.20 を 0.005 だけ超えている。 これは確率的なゆらぎではなく、レシピの定義から決まる定数であり、3 シード・8 つの力学腕すべてで同じ 0.205 を返す。結果として Multicellularity は OP3 の対象から全腕で丸ごと落ち、OP4 の点数も 18 → 17 へ減った。 上限が 21% なら、この 1 レシピは全腕で復活する。次に高いのは Aggressive Predator の 0.135（A5 のみ）で、上限の 2/3 の位置にある。

(2) OP1 の知覚半径上限 R ≤ 150 — 19 本中 4 本（Oscillator・Jelly Fish・Turbulent Runner・Linear Oscillator）が丸ごと NaN。落ちた集合を見ると、上限のすぐ外側に事例が溜まっている: Jelly Fish の最小 R は 150.5（上限を 0.5、率にして 0.33% 超える）でこの 1 行が残れば Jelly Fish は OP1 を持てた。Swinger の 150.39、Playing Catch の 158.86、Multicellularity の 159.59 も同様に僅差である。19 本のうち 3 本が「150 台の R」を持ち、上限 150 はその分布のちょうど真ん中に置かれている。 上限を 160 にすると当たるレシピは 15 本から 17〜18 本へ増える。

(3) OP5 の半径レンジ r ≤ 250 — capped/kr-range-clipped.json は 459 標本中 353 件（77%） を「レンジの端で超過区間が切れていた」と記録している。うち 340 件が上端 r = 250 側、246 件が下端 r = 5 側（両端で切れているものが多い）。A1 は 57 標本すべてが該当する。 つまり OP5 が数えた「連結な超過区間の本数」は、大多数の標本で場の半辺に達したまま打ち切られている。上限を超えた空間スケールに構造が続いているかどうかは、この登録では原理的に見えない。同時に S2 の申し送り §2 が指摘するとおり、r が L/2 に達すること自体が Ripley 等方補正の分散を膨らませており、上限は「見えない範囲を作る」と「帰無を暴れさせる」の両方で噛んでいる。

(4) 走行ステップ数 1200 — capped/unsettled-samples.json は 95 件を記録するが、うち 57 件は A7 である。A7 は 0 ステップなので時点が 1 つしか無く、run.js:150 の前半/後半分割が空配列を作り、mean([]) の NaN が run.js:221 の (r.op1First || 0) で 0 に読み替えられて、|0 − 0.97| > 0.16 で全件が未定常と判定されている。これは力学の観察ではなく算術上の作り物である。 残り 38 件が実質で、内訳は A1 17 件（Insurmountable Wall・Multicellularity・Playing Catch・Blobs が各 3、Cell With 2 Nuclei・Aggressive Predator が各 2、Chaos Cells 1）、A8 7 件、A6 4 件、A3 4 件、A2 3 件、A4 2 件、A9 1 件。登録は「A8 が最も緩和に時間がかかる」と予測したが、実際に未定常が多いのは A1 である（#15）。

(5) N = 200 への丸め — 丸めで 0 個体になった行は 19 本を通して1 件も無い。ただし原典の絶対個体数（Oscillator は 620、Blobs は 300）は落ちており、大規模極限で現れる構造は測れない。

(6) 対象レシピ 19 本 — capped/recipes-not-covered.json に、Sayama のサイトの他のレシピと移植の乱択ゲノム生成を使っていないことが記録されている。19 本を全部使うことで「良いレシピを選んだ」という自由度を消すという設計は、実際にそのとおり実行されている（1 本も選んでいない）。

⑩ S-46（Particle Life）との突き合わせ — 定性の二値でのみ

登録は参照点5 で「符号一貫性の有無という定性の水準でのみ並べる。数値の大小は主張しない」と縛っている。それに従う。

  • S-46: 非対称行列の腕で 0.182 / −0.045 / −0.080 / 0.054 / 0.030、同一行列の複製で 0.118 / 0.134 / 0.093。型ペアごとの追跡関係に一貫した向きは見えていない（符号が割れ、対照のほうが大きい値を出している）
  • S-71: A1 の 17 本すべてで A5（相互作用を切った系）を上回り、15 本で閾値を超えた。ゲノムの組の間に一貫した追跡関係が見えている

二値としては、型ペアの行列を持たない S-71 の側で見え、行列を持つ S-46 の側で見えなかった。 数値の大小は主張しない（定義域も定義も違う）。

ユーザの見立て（「パラメータ数の少なさと集約への還元により、一定以上複雑なパターンは作りにくいのではないか」）については、登録が「OP5 の spatialScaleCount が 19 本中どれだけで 2 以上になったかを事実として報告するだけにとどめ、見立ての当否を判定しない」と決めている。事実: A1 で OP5 が閾値 2 以上になったのは 19 本中 3 本（Slicer・Rotary・Blobs）である。ただしこの数字は見立ての検証に使えない。 A6（単一ゲノム）が 14 本、A7（一様ランダム配置）が 5 本を出しており、この測り方では「複雑さが少ない」と「帰無のほうが多く陽性を出す」が区別できていない（§5）。

事後解析（事前登録していない）

以下は事前登録に無い。判定には使わない。§3 で述べた「A5 の 0.1086 は何か」の定量がこれにあたる。

有限標本の床の式。 各有向量 C(b→a) は、b 行の n_b 個体にわたる cos θ の平均である。向きが等方なら cos の標準偏差は 1/√2 なので、C の標準誤差は (1/√2)/√n_b。ΔC = |C(b→a) − C(a→b)| は独立な2つの差の絶対値なので、その期待値は半正規分布の平均 √(2/π) を掛けて

E|ΔC(a,b)| = √(2/π) · (1/√2) · √(1/n_a + 1/n_b)

もう1つ。 定義文どおりの OP3（時点で平均してから絶対値）を使えば床は √20 ほど下がり、登録の 0.08 と整合するはずである——その場合 A5 は条件(b) を満たしうる。だが生ログには時点ごとの C が残っていないので、これは確かめられていない。確かめるには再走行が要る。 本レポートはこれを「そうなるかもしれない」以上には書かない。

本家サブプロジェクトへの含意（候補として挙げるだけ。要件化しない）

  • 「相手を名指しできない系にも非相反な追跡関係は出るか」に対して、本走行は肯定側の材料を出した——ただし事前登録した判定規則は条件(b) で止まっており、主張としては支持されていない。人工生命の側の含意としては「型ペアの相互作用行列は、非相反な追跡/被追跡関係の必要条件ではない」という候補になる。8 つ組ゲノムの差（とくに知覚半径と力の強さの組み合わせ）だけで、統計的に一貫した追跡関係が現れうる
  • A9 は、それを構成的にも示している——追う側 R=300・逃げる側 R=20 という「誰が誰を見るか」の非対称だけで、ΔC が 0.6 前後になる。行列を持たない系で非相反を作る手続きは存在する
  • ただし帰属は決まっていない。 介入（A2 vs A3）と相関（OP4）が食い違わずに、どちらも「知覚半径 R の差」を支持しない向きへ揃っている。次の1本があるなら、R と c を同時に振る格子を組んで交互作用を見るのが素直だが、それは本レポートが決めることではない
  • 既作の Swift 移植の目視観察は、原典とは別の系を見ていた可能性が高い——壁反発の有無が、ゲノム間の関係の指標を雑音床の 2.2 倍動かす。移植のレシピ名（「Insurmountable Wall」「Playing Catch」等）が指す見た目は、壁のある場での見た目である

限界（この実験が言えないこと）

  1. 再実装の忠実性を原典で確認できていない。 Sayama (2009) の本文は有料誌で到達できておらず、運動規則・パラメータ上限表・境界条件はすべて同著者の再掲 arXiv:1308.3400 からの二次取得である（criteria.json の sourceFidelity）。原典の式と一字一句同じである保証は無い
  2. 主判定量 OP3 の実測値は、criteria.json の定義文どおりの量ではない（§4）。絶対値と時間平均の順序が入れ替わっており、登録した雑音床 0.08 の導出（実効独立数 660）はこの実装の推定量に対して整合しない。この一点で、条件(b) の判定は登録された基準の判定になっていない
  3. 登録した knob 4 本のうち、本番走行で実際に振られたものは無い。 run.js に knob の掃引は1行も無い（torus / knob / segregationRadius / pursuitDirectionEstimator のいずれの文字列も現れない）。内訳: segregationRadius・pursuitDirectionEstimator は実装されていない（S2 の scope cut）。pairDistanceMetric=torus は stats.js に実装されているが run.js は常に {} で呼ぶので、トーラス距離で測り直した結果は生ログのどこにも無い。measurementWindowHalf だけが OP1・OP2 について記録されている（op1First/op1Second・op2First/op2Second）が、OP3 には実装されていない。したがって「半径の選び方で OP2 の陽性/陰性がどこまで動くか」（K-9 の教訓）「方向の測り方で OP3 がどこまで動くか」（K-48）「距離の定義を変えると何が起きるか」（K-21）は、登録したが測られていない
  4. OP5 の陽性/陰性は、この登録の測り方では一様配置と区別できていない（§5）。A7 で 57 標本中 19 本、A5 で 19 本中 5 本が閾値 2 以上を返している。S2 の selftest は独立な一様配置 20 本で 11/20（55%）という誤検出率を実測している。したがって本レポートの OP5 に関する数字は、すべてこの誤検出率と一緒に読むこと
  5. 主判定量に対する解析的恒等式の検算（K-18）は、本番では 1 標本も走っていない（§5）。A7 の OP3 は 57 標本すべて NaN である
  6. A1 における OP1・OP5 の陽性は、ゲノムの多様性が作る構造の証拠として使えない（§5・登録の A6 規則B の条項による）
  7. 独立な初期配置は 3 つしかない（§1）。19 レシピは同一シードなら同じ 200 点から出発する。力学を回す腕では軌道が分かれるが、A7 では 57 標本が 3 通りの点配置に潰れている
  8. 更新順序が原典と違う可能性がある。 S2 の申し送り §5 によれば、既作 Swift 移植は逐次更新（Gauss-Seidel）で、本実装は同時更新（Jacobi）である。criteria.json はこの点を規定しておらず、原典 arXiv:1308.3400 も更新順序に言及が無い。この差が結果を動かすかは測られていない
  9. 速度更新規則の読み取りに解釈が1つ入っている（sourceFidelity ⑤）。移植の acceleration をステップ間で積み増して velocity へ代入する形を「速度そのものの更新」と読み替えてある。読みが違っていた場合に何が変わるかは測られていない
  10. S-46 との比較は定性の二値のみ（§10）。量の定義域も定義も違うので、数値の大小は主張しない
  11. 上限の外側は見えていない（§9）。とくに OP5 は 459 標本中 353 件で超過区間がレンジの端で打ち切られており、r > 250 に構造が続いているかは原理的に測れていない。OP1 の R ≤ 150 は、19 レシピの R 分布の中に事例が張り付く位置に置かれている
  12. 「差が無い」は言っていない。 A8 と A1 が雑音床の範囲内で一致したことは「同一である」ことを意味しない。同一だと言えるのは状態ハッシュが一致したときだけであり（K-36）、本走行でそれが起きたのは A7 の同一シード内（57 標本が 3 つのハッシュへ潰れる）だけである
