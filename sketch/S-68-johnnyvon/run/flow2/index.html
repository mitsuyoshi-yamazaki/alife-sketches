2. 何をやったか

2.1 系

原典の JohnnyVon の規則を写した（criteria.json の system）。2種の T 字の codon（紫・緑）が一辺 165 の箱（周期境界なし・壁で鏡映）の熱浴つきの液体を漂う。腕の先に5色の場（赤・青・紫緑・黄。small 0.01／large 赤青紫緑 4・黄 6）を持ち、赤と青の先端が 0.02 以内・反平行から π/256 以内で結合して一本鎖を作る。一本鎖に入った codon は紫緑の場が large になり、相補の自由な codon を紫緑で捕まえて保持する（鋳型）。保持された隣り合う2つの codon の間に赤青ができて写しが伸び、完成すると局所の状態機械（strand_location_state 0/1/2 と splitting_state x/y/z。自分と結合で指す近傍だけを読む）の y の波と z の波が鎖を往復し、z に入った codon の黄が large になって斥力で鋳型と写しを引き離す。上位の単位（鎖・二本鎖・系譜）はシミュレーションの側に一切書かれていない（selftest.js の局所性の3項目: 状態機械の1回の呼び出しが読む codon は 4 以下、core.js は連結成分・経路探索を持たず観測器を読まない）。

S4 がコードで確かめた登録との対応（原典の規則）:

  • codon の形: 赤 φ+π・青 φ・紫緑と黄 φ+π/2、長さ 7・7・4・1、慣性モーメント 13.89 ✓
  • 5色の場: small 0.01、large 黄 6・他 4。紫緑は自分の赤か青が結合していれば large（NC-notemplate は常に small）。黄は z に入った歩に large、1000 歩で small（NC-nosplit は常に small）✓
  • 結合の生成と切断: 赤青は先端 0.02 未満・角 π/256（M-wide は π/64）・両方の腕が空き。紫緑は半径の和未満・反平行から π/3・large 同士は始めない。切断は先端の距離が半径の和を越えたとき ✓
  • 状態機械の遷移表（Table 4・5）: 登録の fsm の6行を fsmStep の分岐と1行ずつ突き合わせ、近傍がいないときの条件を偽と読むことまで一致した ✓
  • 1 歩の順: 力 → 速度 → ばねの減衰 → 粘性と熱浴 → 位置 → 壁 → 切断 → 生成 → 状態機械と時計 → 入れ替え ✓（入れ替えは δ = 0 で動いていない。§1.6）

4. 独立の検査で見つけた食い違い

数え直しの方法: reports/s4-analysis/rerun.js は実装の core.js の buildInitial・step・stateHash だけを読み（力学は同じ乱数の列で同じ軌道になる）、観測器は detectors.js を使わず criteria.json の observerDetails の文面から書き直した。U1 の同一性は赤青の生成・切断の出来事ごとに場合分けし（自発／鋳型（生成した2つの codon が同じ U1 の隣り合う2つの codon と紫緑で結合）／半保持、鋳型の伸長と融合は古い同一性を保つ、鋳型によらない付加は新しい同一性と変異の印、分断は断片へ）、複製は「写しと鋳型の間の紫緑が全て切れ、両方が生きている」ときに数え、写しと鋳型の配列をその時点で読む。P は向きを揃えて照合し、h₀ は相手も自由な codon に限り、N1 の窓は登録の枯渇（結合を1本も持たない codon が 5 未満）の前に限る。再走行の最終状態のハッシュが本番と一致することで、同じ軌道を数えていることを確かめた（33/33）。

4.3 D₂ が倍増の回数ではなく U2 の大きさだった（N3 が構造上「新」にならない）

4.4 位置だけの検出器との照合のキーの向きが逆だった（②が構造上 0）

  • computePAt は B の赤青の辺を [i, blueBond[i]]（青を持つ側, 赤を持つ側）で作り、P の接触を [i, j]（赤の先端の持ち主 i, 青の先端の持ち主 j）で作って、同じ文字列キー a_b で照合している。向きが逆なので一致は常に 0。positional.jsonl の rbAgree は 50 走行 × 3 つの ε で全て 0 で、そのとき P の接触の数（rbP）は B の結合の数（rbB）とほぼ同じ（M-wide 6801 で 6,536 対 6,482）——同じものを見つけているのに照合で落ちている。
  • 数え直し（S4。向きを揃えた照合）: 赤青の再現率 0.99〜1.00、精度 0.91〜0.99（ε = 1）。紫緑は実装の値とほぼ同じ。

4.5 h₀ が「鋳型に捕まった codon」まで数えていた（N1 を「なし」へ倒した）

  • 登録の h₀ は「自由な codon が、τ_hold 以上続いた紫緑の結合で別の自由な codon を保持していた時間の割合」。実装は「赤青を持たない codon のうち、紫緑の結合の年齢が τ_hold 以上のもの」を数え、相手が一本鎖（鋳型）でも数えた。鋳型に保持されている自由な codon は正に「上の段の性質」の側なので、下の段の値へ上の段の性質が漏れ込んでいる。

4.9 登録そのものの食い違い

  • C2 の後半「NC-nosplit の 4 中 3 以上で N2 がなし」は登録の定義で構造上満たせない。N2 は「完成した U2 が 3 未満なら判定不能」で、NC-nosplit は割れないので完成した U2 は種の写しの 1 本だけになる。登録は NC-nosplit で「N2 がなし（解放 0）」を予測したが、判定の資格が「なし」への到達を塞いでいる。負コントロールが判定の欠けを拾えることを示すはずの条件が、判定不能に吸われた（K-15 の型）。
  • ⑦（止まらない）は走行の長さの上限と区別がつかない: 閉じた R 族で陽性 3 走行は「4×10⁵ 歩ではまだ尽きていない」だった（§3.3）。流れの腕と比べる設計なので、閉じた腕の⑦が陰性であるには、その腕が走行の後半より前に尽きる必要がある。R 族の長さ（原典の枯渇の約 3 倍）は、原典より遅いこの実装では足りなかった。
  • 登録の静的な見積もり「赤青は深い（57.6 ≫ kT）ので窓の中で切れない」は、⑤と④の予測の前提だったが、M 族で赤青の切断が計 8 本起きた（§1.5）。判定は動いていない。

(1) D₂ は倍増の回数ではなく、最大の二本鎖の大きさの log₂ だった。 detectors.js の doublingCount(series) は var base = series[0].size || 1 で基準を取る。系列の最初の標本は t = 0（二本鎖も群もまだ無く大きさ 0）なので、基準は 0 || 1 で常に 1 になり、D は「系列の最大値が 2, 4, 8, … を何回越えたか」＝ ⌊log₂(最大値)⌋ になる。登録の D は「A(t₀) ≥ 1 から始まり、2×10⁵ 歩以内ごとに倍になった回数の最大」である（間隔の制約は実装が notImplemented と明示している）。

5. 本家サブプロジェクトへの含意（候補。要件化しない）

  • 材料の流れは「維持」を作ったが「競争」を作らなかった: codon を一様に入れ替える流れは、閉じた箱では凍って止まる複製を、入れ替えの速さで続く複製に変えた。しかし淘汰に要る2つ目の型は、この δ（codon の寿命が複製周期の 50 倍）では現れず、最初の系譜が材料を拾い続けた。淘汰圧を作るには、流れの量だけでなく、新しい型が既存の系譜に材料を取られる前に立ち上がれること（例: 流れを強くする・空間を広げて系譜を隔てる・変異が複製される）が要る——試していない仮説である。
  • 開いた系では「部品が残る」の分母が変わる: 閉じた系で「凍結」として測定から外れる長命の未完成の複合体が、流れの中では入れ替えで終わり、測定の分母へ入った。H-strict のような「窓の中で残るか」の尺度を開いた系と閉じた系で比べるときは、窓がどう終わるかの内訳を並べる必要がある。
  • 階層の段は流れの有無で変わらなかった（3段・U4 は無い・3つの性質は上の段だけ）。流れは段の数ではなく、最上段（系譜）の時間の振る舞い——止まるか続くか——を変えた。
