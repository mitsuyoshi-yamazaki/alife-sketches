一行で言うと

トーラス上の重力を全鏡像の和として実装すると、力は打ち切りの形（正方 16 枚幅 / 円 半径 16）にも打ち切り位置にも依らず O(1/N) で同じ極限へ収束する（N=16 と N=32 の差は F_med 比 0.71〜0.88%、正方と円の差は 0.10〜0.12%）のに、同じ鏡像集合で計算したポテンシャルは N に比例して発散し、しかもその発散係数は打ち切りの形で変わる（実測 正方 −11.4933·N·ΣGM/L、円 −10.2429·N·ΣGM/L、理論 8ln(1+√2)=7.0510 と 2π=6.2832 に ΣGM=1.63 を掛けた −11.4931 と −10.2416 に 5 桁一致）——発散部は位置に依らない加算定数なので力にも Φ の差にも残らないが、保存量の相対評価の分母に |E(0)| を使うと N=0 で −3.02、N=16 で −186.95 と 62 倍違う数で割ることになり、保存が自明に見える。回り込みそのものは大きく効いた（力の 18.9〜22.0% が最近接鏡像だけの力との差、上位 10% では 55〜76%）が、力の向きを 90°超ひっくり返す検査点は 0.7〜4.0% にとどまり、5 configSeed のうち 1 つは登録閾値 1% を割った。打ち切りが作る人工物は走査刻みを 100 倍細かくしても縮まない真の不連続（最近接鏡像 D=0.47〜0.90、3×3 で 0.15〜0.27、16 枚幅で 0.015〜0.025）であり、その跳びの絶対値は源の配置に依らず 2S = 7.83 / 1.91 / 0.172（GM=1 の源。登録の解析式 2S≈8 / 1.9 / 0.17 と 3 桁一致）。この不連続はポテンシャルを壊さない（力は Φ の厳密な勾配であり続ける。数値微分との相対差 4.2e-7）にもかかわらず、積分器の誤差を通じて保存の判定を落とす——最近接鏡像腕の energyDrift は p95 = 1.44e-3 で登録閾値 1e-3 を上回り（5 configSeed 中 4 つで陰性）、しかもその誤差は全鏡像和腕のような有界振動ではなく一方向に蓄積する（線形回帰の傾き × T が最大偏差に占める割合の中央値: 全鏡像和 0.14 に対し最近接鏡像 0.70）。

何をやったか

題材

一辺 L=1 の平坦トーラス T²（上下・左右を同一視）に、重力の大きさが異なる固定源を 3 つ（GM = 1.00 / 0.45 / 0.18）置き、質点 12 個を初期位置・初速度ランダムで走らせた。力は全鏡像からの寄与の総和である:

F(r) = − Σ_s Σ_{n∈[−N,N]²} GM_s · (d_s + nL) / (|d_s + nL|² + ε²)^{3/2},  d_s = wrap(r − r_s)
Φ(r) = − Σ_s Σ_{n∈[−N,N]²} GM_s / (|d_s + nL|² + ε²)^{1/2}   （力と同一の N・同一の n の集合）

N_img=16（正方 33×33 = 1089 枚）、ε=0.06（Plummer 軟化）、dt=2e-4、20000 ステップ（T=4.0）、velocity Verlet。 問いは創発の観測ではなく実装の成否であり、判定は走行前に固定した閾値つきの機械検査で行う。

腕は 6 本を実走した。A1 登録どおり（N=16・Verlet）／A2 最近接鏡像のみ（N=0。回り込みを完全に忘れる）／A3 3×3 鏡像（N=1。中間項）／A4 重力ゼロ（全 GM=0）／A5 力則は A1 と同一のまま積分法だけ陽的 Euler ／twin A1 と同一で初期位置の x に一律 1e-9 を足した双子。

観測器（事前登録した 6 つの秩序変数）

  • wrapForceFraction 各検査点で w = |F_full − F_min| / max(|F_full|,|F_min|)（F_min は N=0 の力）。回り込み寄与の相対的な大きさ。判定 中央値 ≥0.05 かつ p90 ≥0.30
  • netForceReversalFraction F_full と F_min が 90°超ずれた検査点の割合。ユーザ文言「見かけ上左にあっても右からも受ける」の直接の符号化。判定 ≥0.01
  • forceFieldDiscontinuity カット軌跡（最近接鏡像が切り替わる面）を横切る走査線上の力の跳び D（F_med で正規化）。判定 A1 で ≤0.05、A2 で ≥0.50
  • energyDrift max_t |E(t) − E(0)| / ΔΦ_torus（ΔΦ_torus は格子上の Φ の P95−P05）。判定 p95 ≤1e-3 かつ最大 ≤1e-2。|E(0)| で正規化してはならないと登録が明記している
  • imageSumConvergence |F_N − F_{2N}| / F_med の p95、および正方 N=16 と円 R=16 の差。判定 p95 ≤0.05、形の差 ≤0.02、隣接 N の比 ∈[1.5,3.0]
  • trajectoryDivergenceFromNoWrap A1 と A2 の同一初期条件からのトーラス距離（t=1.0）と、丸め誤差双子との分離の比 R。判定 分離 ≥0.10 かつ R ≥10

静的な 4 つ（前 3 つと imageSumConvergence）は場の性質であり icSeed に依存しないことが登録で名指しされており、実装もそのとおり configSeed ごとに 1 回だけ計算している（fields.jsonl に icSeed の欄が無い）。したがってこれらの真の複製数は 5 であって 60 ではない。本レポートもそう扱う。

D. energyDrift の 3 番目の正規化は、実装では恒真な量になっている

登録の knobs[1] は分母の 4 通りを「ΔΦ_torus = P95−P05 / ΔΦ_torus = max−min / 軌道ごとに実際に訪れた Φ の範囲 / 初期運動エネルギー」と定めている。実装（run.js 224 行）は 3 番目を

visitedPhiRange: (function () { var mn = Math.min.apply(null, series), mx = Math.max.apply(null, series); return (mx - mn) > 0 ? (mx - mn) : null; })()

としており、series は Φ ではなく E（= 運動 + 位置エネルギー）の時系列である。したがってこの分母は max E − min E であり、分子 max_t |E(t) − E(0)| と同じ量から作られている。E(0) は必ず [min E, max E] の中にあるので、この組合せの「max」統計は、どんな軌道でも・どんな腕でも必ず 0.5 以上 1 以下になる。実測もそのとおりで、A1（保存している腕）の p95 は 0.990、A5（保存を壊した腕）の p95 は 1.000 である——この軸は A1 と A5 を区別できない。

C2-e が要求した「16 通りのうち 12 通り以上」はちょうど 12 で成立したが、落ちた 4 通りはこの 1 軸である。すなわち「12/16」という数え方は、独立でない 16 マスを独立であるかのように数えており、実際には「4 本の分母のうち 3 本で成立し、1 本は測り方として成立していない」と読むのが正しい。 登録どおりに「訪れた Φ の範囲」で正規化していれば（Φ の変動幅は軌道あたり O(1) なので）この軸も残る 3 本と同じ側に立ったはずであり、頑健性の検査は 16/16 になったと見込まれる。

実装する者が踏む落とし穴（技術的な知見）

本スケッチが実際に踏んだ順に、周期境界で長距離力を実装する者が出会う癖を並べる。

  1. カット面の上では、素朴な打ち切り窓が非対称になる。 正方窓 d + nL, n∈[−N,N]² を、d がちょうど ±L/2 の点（=カット面）で評価すると、d がどちらの符号に丸まるかで窓が 1 列ぶんずれる。残差はカット面の跳びのちょうど半分 S である（N=16・GM=1 で実測 0.0857。同じ源のカット面の跳び 2S は実測 0.172 なので、その半分に一致する）。丸め誤差 1e-16 とは 14 桁違う。両側の極限を平均する（query ± 1e-9 の 4 象限を平均）と厳密にゼロになる。対称点での恒等式を検査に使うなら、この対称化を最初から組み込む必要がある
  2. 上の残差と、力の場の不連続は同じ 1 つの量である。 どちらも「打ち切り窓の縁にある鏡像の列が 1 列入れ替わる」ことの表れであり、大きさは 2S = (GM/L²)·2Σ_{m=−N}^{N}(N+0.5)/((N+0.5)²+m²)^{3/2}（N=0 で 8、N=1 で 1.9、N=16 で 0.17）。打ち切り N を決めるとは、場に残す不連続の大きさを決めることである
  3. 力しか使わないなら打ち切りの形（正方/円）は自由。エネルギーを使うなら Φ の絶対値は捨てる。 発散係数は窓の形で決まる（正方 8ln(1+√2)、円 2π）が、位置に依らない加算定数なので力にも Φ の差にも入らない。相対誤差の分母に |E| を使ってはならない——N を上げるほど分母が大きくなり、保存が良くなったように見える（本系では N=0 と N=16 で 62 倍）
  4. 不連続な力則は、保存則ではなく積分器の性質を壊す。 力が使ったポテンシャルの厳密な勾配である限り保存則の枠組みは無傷だが、シンプレクティック積分の「誤差は有界に振動する」という性質が失われ、誤差が一方向に積み上がる（傾き×T / 最大偏差が 0.14 → 0.70 へ）。したがって「エネルギーが保存しているか」という検査は、回り込みの有無を判別しない（A2 も A1 も同じ枠組みで保存する）が、積分器が健全かは判別する
  5. ∮F dA = 0 のような恒等式を一様格子の Riemann 和で検査すると、閾値の桁を見誤る。 滑らかな周期関数なら中点則はスペクトル収束するが、カット面のジャンプが O(1/n) に落とす。恒等式の検査を設計するときは「その恒等式をどの求積法で確かめるか」まで一緒に決める
  6. 数値微分で力則を検算するときの刻みは ε_mach^{1/3} ≈ 6e-6 の近傍に置く。 h=1e-6 は最適点の手前で丸めが効き、相対誤差が 4.1e-6 まで悪化する（h=1e-5 なら 4.2e-7）
  7. 相互作用しない試験粒子の系では、丸め誤差双子は全粒子を等しく揺らす。 1 粒子だけ揺らすと残りは完全に同一軌道を辿り、中央値がゼロに潰れて比が無意味になる（実装者が smoke test で発見・修正済み。raw/notes.md §3）

1. 鏡像は別の天体ではない（概念の側）

トーラス上の鏡像は、同じ1個の源を、平面の別の写しから見ているだけである。core.js の fieldAt は源ごとに最近接鏡像変位 d_s = wrap(r − r_s) を取り、そこへ (n_x, n_y)·L を足した 1089 個の寄与を足す——足されている 1089 個は 1089 個の天体ではなく、1 個の天体を 1089 回数えたものである。

4. main.md と Claude の返答に対して、何が変わるか

判定は何も変わらない。 以下は理由の側の訂正・補強である。

4-1. 「力は Φ の厳密な勾配であり続ける（相対差 4.2e−7）」は、カット面の上では成り立たない

main.md の「一行で言うと」と controls.json の numericGradientCheck は、h=1e−5 の数値微分と力が 1000 点で相対差 4.2e−7 に収まることを根拠に、不連続が Φ を壊さないと述べている。しかし:

  • 3 源のカット面（縦3本・横3本）から h=1e−5 以内に落ちる確率は 1.05e−4（100 万点で実測）。1000 点の検査が 1 点でも踏む確率は約 10% である。この検査は構造的にカット面を見られない。
  • 実際にカットを跨ぐ点で測ると、相対差は 1.07e−3 / 3.17e−2 / 1.57e−1（3 本のカットそれぞれ）。カットを外した点は 3.17e−9 である。

正しい言い方は「Φ はカット面で連続だが折れ目を持ち、片側微分どうしは 2|F_n| だけ食い違う。F が −∇Φ なのはカット面を除く全域である」。結論（Φ は壊れない＝保存は原理的に保たれる）は変わらないが、それを支えるのは勾配検査ではなく ΔΦ = 0 のほうであり、登録された検査は後者を測っていない。これは main.md が挙げた検出器と登録の食い違い（A・D）と同種のもので、5 件目にあたる。

4-2. Claude の返答（r-abd62fa68b6a）の評価

返答の主張判定
「本レポートの実験はこれを検証していません。A6 は走行されていない」正しい。事前登録の走行では答えられない
「力は位置エネルギーの厳密な勾配であり続けるため、系全体のエネルギーは原理的には保存されるはず」結論は正しいが、根拠として不足。勾配であることは各領域内の話で、一周したときに Φ が元に戻るか（一価性）を言っていない。そこを言わない限り「全体では保存しない」の否定になっていない。しかも根拠に引いた 4.2e−7 はカット面を見ていない（4-1）
「Φ が元の値に戻れば運動エネルギーも元に戻る一種の周期軌道になり、無限に加速し続けることはできない」正しいが「Φ が元の値に戻れば」が仮定のまま置かれている。戻ることの証明が問いの本体であり、本レポートが埋めたのはそこである
「鏡像でスイングバイして」という前提そのもの返答は前提を訂正していない。鏡像は別の天体ではなく、静止した源からはエネルギーを奪えない（§1）。ここを言えば、走行の有無に関わらず即答できた
「事後解析として…検査を追加登録する形が適切」本レポートは追加登録せず事後解析として実施した。§2 の循環積分は走行を要さず、fieldAt だけで厳密に答が出るため、登録・再走行の必要が無かった
