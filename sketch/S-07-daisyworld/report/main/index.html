一行で言うと

裸の惑星が 5.6℃ から 49.9℃ へ 44.4℃ 動く光度区間（L = 0.75 〜 1.35）で、ヒナギクの住む惑星は 19.5℃ 〜 26.1℃ の 6.6℃ しか動かない。 誰も気温を測っておらず、核には「保つ」という語も分岐も 1 つも無い——あるのは被覆率・アルベド・温度・成長率だけである。同じ住人のまま熱輸送 q を 0 にすると、この鈍感さは跡形もなく消える（幅 0.654 → 厳密に 0、温度は裸の惑星と機械精度で一致）。あわせて、事前登録した負コントロールの 1 つが、本番前の検査で「負コントロールではなかった」ことが判明した——K-14 が言う「負コントロールを複数そろえよ」の一段手前に、「負コントロールの設計自体が間違いうる」という段があった。

何をやったか

題材

黒いヒナギクと白いヒナギクだけが住む惑星がある。黒は光をよく吸うので周りより暖かく、白は反射するので周りより涼しい。どちらも同じ温度で最もよく育つ（22.5℃、5℃ と 40℃ の外では育たない）。恒星の光度が上がっていくとき、誰も気温を調節しようとしていないのに、惑星の気温が広い光度範囲で一定に保たれる——というのが原典の主張である。これを定義から実装して測った。

この題材を選んだ理由は、比べるべき対照が理論から一意に決まることにある。「ヒナギクが 1 株もいない惑星」の温度は光度から解析的に出る（σT⁴ = S·L·(1−A_地面)）ので、鈍感さは「住人のいる惑星の温度変化 ÷ 被覆ゼロの惑星の温度変化」で測れ、帰無値は厳密に 1.0 になる。長さのスケールも時間のスケールも選ばない（K-10）。

核の作り方——「ヒナギク」も「保つ」も核には無い

核が持つのはこれだけである:

A        = Σ α_i·a_i + α_空·a_地面            表面の反射率
σT⁴      = S·L·(1 − A)                        表面の平均温度
T_i⁴     = q·(A − a_i) + T⁴                   型 i が局所的に感じる温度
g_i      = max(0, 1 − ((22.5 − T_i)/17.5)²)   型 i の増加率
dα_i/dt  = α_i·(α_空·g_i − γ)                 面積分率の時間変化

輪になっているのは式であって、意図ではない。 局所温度が反射率に依り、反射率が面積分率に依り、面積分率が局所温度に依る。この輪のどこにも「目標の温度」も「ずれを打ち消す」も無い。core.js には BOUNDARY: OBSERVER の行があり、selftest.js がその行より上に上位概念の語（恒常性・調節・目標値・生命・ヒナギク・regulate・homeostasis など 16 語）が 1 つも現れないことを機械照合する。「ヒナギク」という呼び名も、「保たれている」という判断も、境界行より下の観測器とレポートの側にしか無い。

対照系はすべてパラメータの値の差として表せるようにした（核に分岐を足さない）——アルベドを地面と同じにする／q を 0 にする／q の符号を反転する／成長曲線の幅を極大にして温度依存を消す／被覆型を空にする。

s(L) = |ΔT_住人あり| / |ΔT_被覆ゼロ|（中心差分）。regulatedWidth は s(L) ≤ 0.5 となる格子点の幅である。

内側の閾値 0.5 には理論的な根拠がある: アルベドが光度に依らず一定な系では s は必ず ((1−A)/(1−A_地面))^(1/4) になり、本スケッチのアルベドが [0.25, 0.75] に収まる以上、定数アルベドの系が取りうる s は [0.841, 1.107] に限られる。0.5 を下回るには、アルベドが光度に応じて動かねばならない。

妥当性検査（31 項目すべて通過。node selftest.js）

正コントロールは、実装から独立した解析的な恒等式にした。2 型が共存する定常状態では α_空·g_黒 = α_空·g_白 = γ なので g_黒 = g_白、成長率が 22.5℃ を中心とする偶関数である以上、2 型の局所温度は 22.5℃ について厳密に対称でなければならない。これは定義だけから出る。実測は L = 1.05 で T_黒 = 27.480700℃ / T_白 = 17.519300℃、中点 22.500000000℃（最大ずれ 1.7×10⁻¹³ ℃）。

負コントロールの設計自体が間違っていた（K-14 の一段手前）

事前登録の初版では、負コントロールの 1 つを「熱輸送 q の符号を反転した 2 型」にしていた。理屈はこうだった——q が負なら暗い面が局所的に冷たくなるので、帰還の符号が反転し、温度は保たれなくなるはずである。

本番を 1 度も走らせる前の妥当性検査で、この系が連言を通過した（幅 0.518・slopeRatioMin 0.124）。

分析が誤っていた。q の符号は「どちらの型が寒い側の専門家になるか」を入れ替えるだけで、ある型の被覆率が惑星温度に対して持つ傾きを反転させない。 成長曲線の上り斜面にいる型は、q の符号がどちらでも「惑星が暖まるほど増える」——そして明るい型が増えれば惑星は冷える。負の帰還は残る。

実際、q < 0 の腕は温度を保つ。ただし保たれる場所が違う: 22.5℃ ではなく、2.0℃ 〜 13.7℃ という成長域の寒い端に貼り付く（L ∈ [0.71, 1.23]、幅 0.518）。q < 0 では明るい型が局所的に暖かいので、明るい型だけが寒い惑星で成り立ち、増えては冷やすという暴走が、明るい型の局所温度が成長の下限に触れたところで自ら止まる。同じ機構が、違う温度を保つ。

そこで rev2 で、これを負コントロールから腕へ移し、代わりに本当に増幅する系（暗い型の成長最適を 80℃、明るい型を −40℃ に置いた 2 型）を負コントロールに加えた。これは s の中央値 1.06・振れ幅 145.5℃ で、確かに増幅した。

知見として言えること: K-14 は「負コントロールを 1 種類で済ませるな」と言う。本スケッチはその一段手前に穴があることを示した——負コントロールは、こちらが思ったとおりのものになっているとは限らない。 「これは目当てのものではないはずだ」という設計そのものが仮説であり、検査を要する。ここでそれを捕まえられたのは、負コントロールを 5 種類そろえて、全部が落ちることを本番の前に確かめたからである。1 種類だけを用意して通過させていたら、「検出器が偽陽性を出した」と誤って結論していた。

本家サブプロジェクトへの含意（候補として挙げるだけ。要件化しない）

  • 「性質が現れたか」は、その性質を持たない対照との比でしか測れない。本スケッチは対照が理論から一意に決まる珍しい題材だった（被覆ゼロの惑星の温度は解析的に出る）。人工生命の本家で「どの自由度がどの生命的性質を初めて可能にするか」を問うとき、その自由度を外した系が定義できるかが、問いの立て方の前提になりうる
  • 同じ機構が「保つ」と「壊す」の両方を担う。本スケッチの s は、鈍感な区間では 0.0008、崩れる点では 29.4 になる。安定性の指標と脆さの指標が同一の量であることは、観測器を 1 つ定義するときの設計判断になりうる
  • 多様性は中身を選ばなくても効く。アルベドを乱数で引いた 20 型は、慎重に選んだ 2 型より広い域で温度を鈍感にした（0.932 対 0.598）。「良い部品を選ぶ」ことと「部品を増やす」ことが同じ方向を向く場合がある

限界（この実験が言えないこと）

  1. これは 0 次元の常微分方程式であり、空間が無い。原典も 0 次元だが、本スケッチの結果から「空間があっても同じ」とは言えない（空間があると何が変わるかは S-06 の主題だった）
  2. 進化が無い。アルベドも成長曲線も固定で、変異も選択もしていない。「多様性が効く」という結果（N の掃引）は、多様性が生まれる過程については何も言っていない——最初から N 個ある系を比べただけである
  3. 種の掛け方が原典と同一ではない。原典は L を変えるごとに 0 なら 0.01 を初期値に置き直す。本実装は下限 0.01 を常時掛ける。履歴依存の測定はこの違いに敏感でありうる——下限を外せば一度絶えた型は戻らないので、履歴依存はもっと強く出るはずだが、それは測っていない
  4. q = 2.06×10⁹ は、掃引の寒い端（L < 0.637）で原典が示した物理的な制約 q < 0.2SL/σ を破っている。鈍感さが出た区間（L ≥ 0.748）は制約の内側にあるが、寒い側の履歴依存（L = 0.63〜0.71）は制約の外で起きているので、この 1 点は原典の枠組みでの解釈ができない
  5. 光度の掃引域 [0.5, 1.8] は自分で決めた。原典は図の光度範囲を本文に書いていない。regulatedWidth は絶対値（光度の幅）で登録してあり掃引域で割っていないので、掃引域を広げれば閾値 0.3 の意味は変わらないが、「掃引域の何割か」という読み方は変わる
  6. 「黒のみ」の判定は内側の閾値に依存する（0.25/0.50 で落ち、0.75 で通過）。登録値での判定は「落ちる」だが、これを結論として扱ってはいけない
  7. 絵が意味を成しているかは確認できていない（method の既知の弱点）。viewer.html が呼ぶ核の関数が実在することと、ES module でないことは機械検査したが、配色・レイアウト・「目で見て分かるか」はユーザが最初に開いたときに初めて分かる
  8. 準静的な掃引であり、光度が速く変わる場合を測っていない。stepsPerL を 8 倍にしても結果が変わらないことは確かめたが、それは「もっと遅くしても同じ」を示しただけで、速い変化への追随は測っていない
