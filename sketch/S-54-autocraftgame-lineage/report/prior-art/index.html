1. AutoCraftGame とは何か

自己複製可能な自律キャラクターによる人工生命シミュレータを目指す、ユーザ（本リポジトリ所有者）の別プロジェクトである。最終目標はリポジトリの README が一文で述べている:

最終目標は、進化手法をゲームシステムとして提供せず、個々のキャラクター（人工生命）の自律的な活動の結果として進化が創発するシミュレータの実現。 — README.md @8bb4f34

構成は「版ごとに独立した npm プロジェクト」である。

各バージョンは独立したnpmプロジェクトとして格納される。バージョン間のコード依存はない。 — README.md @8bb4f34

この一文が本スケッチの符号化の前提を決めている。版間にコード依存が無いので、「引き継がなかった機構」をコードの削除では判定できない（D4 は仕様の語彙の消失で取った）。また各版が別の切り口から作り直されているので、要件の達成状況が後退しうる（実際に後退していた。§3）。

4. 同じ袋小路は繰り返されたか（P1）

事前登録の予測 P1 は「『複製はできるが変異が表現力を持たない／変異が入る余地が無い』系の袋小路が、2つ以上の版で繰り返される」だった。2版どころではなかった。

v4未達成: 適応的進化の証拠なし（戦略空間が狭く、自然選択圧が不十分）

v8未達成: 自己書き換え能力の欠如（プログラムはI/O経由で外部のみ書き込み可能、自身のメモリには書き込めない）

9版中6版が、同じ一つの袋小路で終わっている。 （機械の数え方——D3 の本文に「変異」の語を含む版——では 5版で、v4 の「適応的進化の証拠なし」を「変異は在るが適応を生まない」という同じ袋小路の別の言い方として手で足すと6版になる。どちらで数えても、事前登録の予測「2版以上」は超えている） しかも現れ方が版ごとに違う——v1 は「機構が無い」、v4 は「あるが効かない」、v6 は「数値しか変わらない」、v7 は「完全に一致してしまう」、v8 は「自分に書けない」。同じ壁に、毎回ちがう角度からぶつかっている。

これが v7/v8 の袋小路（原子的コピーで変異ゼロ、あるいは自己書き換え不能）を抜ける鍵だった。 v9は「忠実コピーはデフォルト、変異はオプトイン」という設計で R2×R6 を両立させた — v9/docs/CONCLUSION.md @8bb4f34

忠実度が系にある側の代表は Avida である（本調査では C1 のみの M1）。設定ファイルの2行が、AutoCraftGame の R6 がまさに禁じている形を示している:

MUT_RATE_SOURCE 1 # 1 = Mutation rates determined by environment. # 2 = Mutation rates inherited from parent. — avida.cfg（devosoft/avida）

「変異率を環境が決めるか、親から継ぐか」を選ぶこと自体が設定項目になっている。 DOI 10.1162/106454604773563612 の本文へは到達できなかったので（§6）、判定は公開ソースの設定ファイルから行った。

M2 には届かなかったが、C3 の線がどこにあるかを一番はっきり見せたのは Darwinbots である。bot は .mrepro を使って「わざと不完全に複製し、子に変異を強いる」ことができ、その率は系の設定を無効にしても効く:

Bots can also force mutations on their children by imperfectly reproducing using .mrepro.

それでも C3 を満たさないのは、.repro という複製の原語を系が持ち、忠実度も系が2通りに定めているからである。 主体が選べるのはその2つのどちらかであって、忠実度そのものではない。「2値のスイッチ」と「プログラムが書くアルゴリズム」のあいだに、もう一本の線がある。

4.2 Stringmol と Squirm3 — 人工化学は C2 を満たす

本調査で分かった構造のひとつは、「人工化学は C2 を満たすが、セルオートマトンとプログラムスープは満たさない」ということである。

Stringmol の仕様書は、C2 の条件そのものを一文で述べている:

The model is an artificial chemistry in which the unique properties of each molecular species is encoded as a sequence of symbols. ... There is no distinction between genotype and phenotype, or data and program.

複写も分子の側にある:

Copying is a bi-molecular process in which one partner acts as the template and one acts as the copier.

Squirm3 も同じ形である:

an AC is a triple (S, R, A) where S is the set of all possible molecules, R is a set of collision rules and A is an algorithm describing the domain and how the rules are applied to the molecules inside (the physics).

複製子は世界のすべての分子と同じ集合に属し、同じ衝突規則で変換される。主体だけの特別な生成経路が無い。 これは C2 の定義がそのまま当てはまる。

この線引きは本スケッチの裁量である。 同じ議論をセルオートマトンに当てると、Langton のループも von Neumann 万能構成子も C2 を満たすことになりかねない。本スケッチは「分子種と反応規則を明示的に持つ系は C2 を満たし、セル状態の遷移規則しか持たない系は満たさない」と読み分けた。別の読み方なら M 段の分布は変わる（事前登録の限界④が警告していた「C2 の線は揺れる」がここで実際に揺れた）。

4. どんな制約が現れたか（N2 の根拠）

本記録の価値は、制約が4回入れ替わる過程を1本に収めたことにある。

情報原子(I)は世界に 1,209 個しかなく（rare 資源6ノード × 200）、終了時にはその大半が地面に散っていた（PatternChain 497 + EncodedFragment 388 + InfoSeed 164 ＝ 1,049個）。拾い上げは射程内に写ったものだけを1個ずつ拾うので、死骸が世界中に散るほど回収が追いつかない。

5. R1〜R9 のどのマスを動かしたか（N3 の根拠 — 満たさない）

動かしていない。 本記録が扱う「繁殖能力（寿命 × 生涯の子の数）」は、v9 が立てた R1〜R9 の要件表の外側にある量である。v9/docs/CONCLUSION.md は本記録を「進化のプログラマビリティ」の節で引くが、要件表のマスへは結び付けていない。

これは欠点ではなく、本記録の性格である。 要件表は「何ができるか」を並べたもので、「どのくらい上手にできるか」の軸を持たない。本記録が示したのは後者——同じ部品・同じ物理法則・同じ環境で、点検を入れる位置と持参金の中身を変えただけで繁殖能力が2〜3倍変わる——であり、その軸は要件表に無い。

記録自身はこう位置づけている: 移動複製種と長命移動複製種を同じ世界に置けば後者が選択されるはずで、それは進化がシステムではなくプログラムの側で起きることの、もっとも直接的な実例になる。ただしその競争は、この記録の中では走らせられていない。
