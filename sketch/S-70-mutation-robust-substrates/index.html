一行で言うと

到達できた 34 の処理系の中に、人が任意の振る舞いを書けて（①満たす）、かつ記述の変化が表現型を変えないか連続に変える（②満たす）ものは 0 件だった。①を満たす 6 件の頑健さはほぼ「中立（N）」だけで作られており（連続 C を持つのは線形 GP の定数の摂動 1 件）、連続を持つ処理系は、人が書く離散の層と学習・変異が動かす連続の層を分けている——AutoCraftGame の AL-15（中立か致死への二極化）を解く側の「連続」を借りるなら、処理系に「人が書かない連続の層」を一つ足すことになる。移せる手法として 6 つを順位づけ、個別レポートにした。

何をやったか

問いと判定器（登録のまま）

  • 要件①（R1）: 人が任意の振る舞いを書けるか。表現力（Q1a）・書く経路が実在するか（Q1b）・経路が表現力の全体に及ぶか（Q1c）で「満たす／部分的／満たさない」。条件と行動の規則表（ユーザが不採用にした案 D）は ruleD で機械的に「満たさない」
  • 要件②（R2）: 記述データの最小編集が表現型をどう変えるか。編集の種類ごとに N（定義上ちょうど変えない）・C（連続: C1 連続値の連続関数／C2 順序を持つ量への一段の編集）・J（跳び） を付け、全編集種が N か C なら「満たす」、一部なら「部分的」
  • subcode（N か C のどちらで満たすか）を集計の主軸にした。AL-15 の二極化を解くのは C の側で、N は致死を減らすが傾斜を作らない（登録 observers.R2.subcode）

  • 意味を狙う変異演算子（GSGP・SOMO・意味の逆伝播）と LLM を変異演算子にする方式（ELM）は、写像の subcode が「なし」なので M2 を文言どおりには満たさない。登録の locusRule は「演算子の手法も推奨から外す規則ではない」と書いており、M2 の文言と食い違う（限界の節）。どちらにしても ranking ② は演算子を符号化・解釈器より下に置き、ユーザの案 B（実行の意味を頑健にする）の外にある

  • 生存の平らさ（高変異率で頑健な遺伝子型が選ばれる）は処理系の部品の変更ではなく条件の側にある。登録の注記どおり処理系の手法とは混ぜず、「前提の側」として別に置く（ユーザが案 A を「手法ではなく前提」と評価したのと同じ位置）

AutoCraftGame v9 のどこへ移すか（A6）と代償（A5）

MemoryCore（opcode の割り付け表）だけで入る。v9 の opcode 欄は 6bit（64 符号）で、定義済みは約 34 命令、残りは未定義で NOP になる。

  • 縮退（N）: 未定義の約 30 符号を NOP に落とす代わりに、各命令に複数の符号を割り当て、1bit 違いの符号の多くが同じ命令になるようにする。v9 の「未定義→NOP」は「命令の効果が消える」縮退で、こちらは「同じ命令のまま」の縮退である
  • 近さの割り付け（C2）: 1bit 違いの符号を意味の近い命令に置く。例: ADD↔ADDI、BEQ↔BEQL（短い分岐と長い分岐）、LW↔LWL。何を「近い」とするか（遺伝暗号の極性尺度に当たるもの）は v10 の側で決める必要がある
  • 即値欄: Gray 符号にすると、隣の値どうしが1bit 違いになる（手法 1 と重なる）
  • アセンブラ（program-builder）が割り付けを隠すので、アセンブリで書く①は変わらない

代償:

  • 64 符号に約 34 命令なので、縮退の余地は限られる（遺伝暗号は 64 符号に 20 語＋終止）。語長を増やせば余地は増えるが MemoryCore の大きさが増える
  • 「意味の近さ」は1次元に並ばない。ある命令の 6 つの1bit 隣を全部近い命令にすることはできない（遺伝暗号も最適ではない——本文は「高度に、ただし最適ではなく頑健」と書く）
  • CHECKPOINT の魔法の値のように、わざと遠ざけたい命令（偶発的に発火すると困るもの）もあり、近さの割り付けと両立させる設計が要る

一行で言うと

人は離散の言語でプログラムを書き、処理系はそれを連続の基盤（神経網の重み）へ翻訳して実行する。変異は翻訳後の重みに掛けるので、表現型は重みの連続関数になる（C1）。Tracr（RASP を変換器の重みへ）と Parrot 変換（命令型コードの区間を神経網へ）の 2 系に現れた。書く層と変異する層が別になるので、書いた記述と進化した記述が乖離し、進化した個体を人が読み書きできなくなる代償がある。

a program transformation that selects and trains a neural network to mimic a region of imperative code [Q-N10-1]

  • 小さく入れるなら、祖先種の一部の区間（例: PLAN の工程を選ぶ判断）だけを翻訳して重みにし、残りは v9 の命令のまま残す分け方がある（Parrot の「区間を置き換える」型。推論）

  • 記述の冗長さ: 翻訳後の重みは元のプログラムより大きくなる（符号化者の推論。本文で大きさを比べてはいない）

  • 近似誤り（Parrot）: 翻訳が学習による近似なら、祖先種の振る舞いは書いたとおりにならない

手法 1: 連続の数値欄

主レポート: main.md。判定の根拠は raw/coding.jsonl、手法の判定は raw/methods.jsonl。出典は末尾。

一行で言うと

命令・接続・工程といった離散の骨格はそのままにして、そこに数値の欄を持たせ、変異をその値への小さな一歩（±δ・正規分布の摂動）として起こす。到達した母集団では 8 系に現れ、そのうち線形 GP は①を満たす処理系で C を持つ唯一の例だった。v9 には即値欄がすでにあるので、変える単位は「即値欄の変異の起こし方」（複製）か「即値欄の符号化」（MemoryCore）で済む。ただし v9 の PLAN の「回数 ±1」はすでにこの型で、それでも二極化した（main.md の事後の節）。

手法の定義（原典から）

線形 GP は、命令の中の定数を現在の値からの正規分布の一歩で変える変異を定義している。

Change constant c through a standard deviation d const from the current value [Q-S4-2]

同じ本文は、命令内の変異（演算子・レジスタ・定数の置換）を別に定義しており、演算子とレジスタの置換は跳び（J）のまま残る。∂4 は人が書く下書きに「穴」を置き、穴の中身を学習で埋める。

enables programmers to write program sketches with slots that can be filled with behaviour trained from program input-output data [Q-S11b-1]

遺伝子制御網の模型では、接続の構造は離散のまま、しきい値や拡散係数を連続の値として変異させる（Fujimoto ほか）。

the threshold value of each connection [Q-N20-2]

どの処理系に現れ、どう判定されたか

NEAT（C2）満たさない部分的C接続の重み節点・接続の追加
CPPN（S14）満たさない部分的C接続の重み構造の追加・活性化関数

R2 を「満たす」になったのは、骨格を固定して数値欄だけを変異させる GRN 模体だけ。骨格も変異させる処理系では、骨格の編集が J として残り「部分的」になる。

AutoCraftGame v9 のどこへ移すか（A6）と代償（A5）

v9 には即値欄がある（ADDI の 4bit、LI の 16bit）。問題は変異がビット反転で起きることで、2 進整数のビット反転は最下位 bit を除いて ±1 にならない（C0 の判定では J）。

  • 複製（変異演算子）の側: 即値欄を「数値」として扱い、ビット反転ではなく ±1（あるいは小さな幅の一歩）で変える変異を足す。Processor・MemoryCore の意味論は変えない。アセンブラで書く①は損なわない
  • MemoryCore（符号化）の側: 即値欄を Gray 符号で持ち、1bit 反転が隣の値に写る割合を上げる。ただし Gray 符号でも、1bit 反転が常に隣の値になるわけではない（隣の値どうしが 1bit 違いになるだけ）。GE の論文も Gray 符号の局所性を論じている
  • 処理系（PLAN）の側: 工程表にしきい値・確率・時間切れのような数値欄を足し、その値を一歩ずつ変える

代償:

  • 数値欄が効くのは、その値が算術や連続の量に入るときだけである。比較（BLT/BGE など）に入る定数は、しきい値をまたいだところで振る舞いが跳ぶ——1個体の1回の実行で見ると J になり、連続なのは「環境の分布の上で、しきい値を越える状況の割合」だけになる
  • 数値欄を持つ命令の割合をどう決めるか（線形 GP でも設定の一つ）
  • 骨格の編集（命令の置換）は J のまま残る。この手法は二極化を「減らす」が、骨格の変異の二極化は消さない

AL-15 のどちらの側に効くか

中間を作る側（C）。数値欄の一歩は、表現型（出力・行動の量）を一段だけ動かす。

ただし v9 の PLAN の「回数 ±1」はすでにこの型であり、AL-15 の観測ではむしろ最も繁殖に至りにくい編集だった（子を出した割合 33%）。控えの説明では、回数の一歩が材料収支を崩し、失敗が無限再試行になる崖へ落ちる。記述→表現型を連続にしても、表現型→生存に崖があれば傾斜は出ない——この手法を入れるときは、祖先種インタプリタの失敗の扱い（時間切れ・部分的な成功）を並べて検討する必要がある見込みが高い（推論）。

手法 6: 一致の度合いによる照合

主レポート: main.md。判定の根拠は raw/coding.jsonl、手法の判定は raw/methods.jsonl。出典は末尾。

一行で言うと

Banzhaf の人工制御網（ARN）では、蛋白質が制御部位に結合する強さを XOR で数えた一致 bit の数で決め、その数を指数関数に通して信号にする。制御部位の1bit 反転は一致数を ±1 だけ動かし、信号を一段だけ動かす（C2）。v9 のラベル照合は厳密一致（ラベル id の1bit 反転は、別のラベルへの跳びか、一致なしの NOP）なので、そこを「最もよく一致するものへ、一致の度合いに応じて」に広げる手法である。

手法の定義（原典から）

which returns the degree of match as the number of bits set to one (that is, the number of complementary bits between both binary strings) [Q-N14-2]

信号は一致数を指数関数に通して計算され、最大の一致に近いものだけが効く。

Because of the exponential, only proteins whose match is close to u_{max} will have an influence here. [Q-N14-3]

同じ本文は、蛋白質の各 bit を遺伝子配列の 5 組の多数決で決める（1bit の反転の多くは中立になる。推奨表 8 位の「多数決の冗長符号」）。

どの処理系に現れ、どう判定されたか

処理系R1R2subcode一致の度合い（C2）ほかの編集
ARN（N14）満たさない部分的N+C制御部位の反転 → 一致数 ±1 → 信号が指数的に一段遺伝子配列の反転は多数決で N、プロモータの反転は J（遺伝子が生まれる・消える）

ARN は①を満たさない。M1 は但し書き（手法が符号化の側にあり、ラベル照合の置き換えは v9 の①を損なわない）で満たした。

関連する N の側の機構: Tierra・Avida のテンプレート番地（相補パターンの最も近い一致へ飛ぶ）は、照合を「最も近い場所」で解くが、一致は厳密である。ARN は「一致の度合い」を連続の強さにする点でそれより先へ行っている。

AutoCraftGame v9 のどこへ移すか（A6）と代償（A5）

Processor（JMPL/LWL/SWL のラベル照合）。v9 はラベル id（10bit）の厳密一致で、最低番地の LABEL を探す。

  • 最もよく一致するものへ（離散のまま）: 照合を「ハミング距離が最小の LABEL」にする。ラベル id の1bit 反転は、一致の最良が変わらなければ同じ飛び先（N）になる。変われば跳ぶ（J）。一致なしで NOP になる場合が減る
  • 度合いに応じた強さへ（連続）: 飛び先・読み書き先を一致の度合いの重みで混ぜる。これは手法 2（番地の分布化）と組み合わせることになり、Processor の実行単位を変える大きな変更になる
  • 行動の選択へ: 祖先種の行動（PLAN の工程）を、状態と工程の「一致の度合い」で重みづけして選ぶ形にすれば、ユーザが有効と評価した案 C（並行する制御）の実装の一つになる（推論。ARN はもともと連続の制御の力学系である）

代償:

  • 離散のまま（最小距離へ飛ぶ）だと、C2 の性質は失われ、N を増やす手法になる。連続のままだと手法 2 と同じ計算量と行動の離散性の問題を抱える
  • ARN の指数関数（β）は「最大の一致に近いものだけが効く」ようにするもので、β が大きいと実質的に厳密一致へ戻り、小さいと多くの候補が混ざる。度合いの幅は設計の変数になる
  • 照合の最大一致（umax）が変わると全体の正規化が動くので、1bit の反転が全体に波及しうる（C2 の「有界」は、最大一致が変わらない範囲での性質）

AL-15 のどちらの側に効くか

中間を作る側（C）。ただし離散のまま入れると N の側（致死を減らす）になる。どちらで入れるかで効く側が変わる。

手法 2: 番地の分布化

主レポート: main.md。判定の根拠は raw/coding.jsonl、手法の判定は raw/methods.jsonl。出典は末尾。

一行で言うと

番地を「1つの場所」ではなく場所の上の分布（重み）として持ち、読み出しは重みつきの平均、書き込みは重みに比例した混合、飛び先は重みつきの継続にする。神経計算機（NTM・NRAM・神経スタック・スタックつき RNN）と ∂4 の 5 系に現れた。番地を指す記述が少し変わると、読み書きの対象が少しずれるだけになる（C1）。v9 のラベル番地は厳密一致の1点なので、ラベル id の1bit 反転は別のラベルへの跳び（J）になる——そこを連続にする手法である。

手法の定義（原典から）

NTM は、読み書きを全メモリ要素との度合いつきの相互作用として定義する。

We achieved this by defining ‘blurry’ read and write operations that interact to a greater or lesser degree with all the elements in memory [Q-S9-2]

NRAM は、レジスタの値そのものを値の上の分布として持つ。

each register represents an integer value with a distribution over the set [Q-B1-1]

神経スタックは、スタック・キューを連続に微分可能な形で実装する。

implement continuously differentiable analogues of traditional data structures such as Stacks, Queues, and DeQues [Q-B2-1]

∂4 は、Forth の機械の状態（データスタック・戻りスタック・ヒープ・プログラムカウンタ）を連続の表現へ写す。

We map the symbolic machine state S=(D,R,H,c) to a continuous representation [Q-S11b-3]

どの処理系に現れ、どう判定されたか

処理系R1R2subcode分布で持つもの
NTM（S9）満たさない満たすC読み書きの番地（注意の重み）
NRAM（B1）満たさない満たすCレジスタの値・番地
神経スタック（B2）満たさない満たすCスタックの各要素の強さ
スタックつき RNN（B3）満たさない満たすCPUSH/POP の度合い

①を満たさない 4 系は、記述データが学習する重みだけの処理系で、②は満たす。①を部分的に満たす ∂4 だけが、人が書く下書きとこの手法を同居させている（M1 はこれで満たした）。

AutoCraftGame v9 のどこへ移すか（A6）と代償（A5）

v9 の番地の解決は3か所: ラベル番地（JMPL/LWL/SWL。ラベル id の厳密一致で最低番地の LABEL を探す）、レジスタ間接（LW/SW）、分岐の相対オフセット（BEQ など）。

  • Processor（番地の解決）: ラベル照合を「一致の度合い」の分布にし、LWL は候補の値の重みつき平均を読む、SWL は重みに比例して書く。JMPL の「重みつきの継続」は、複数の実行の流れを重みつきで同時に持つことになり、Processor の実行単位を変える大きな変更になる
  • MemoryCore: ヒープ（pmem）の読み書きを重みつきにするなら、語の値を実数（または分布）で持つ必要がある
  • 小さく入れるなら、データの読み書き（LWL/SWL）だけを分布化し、制御の流れ（JMPL）は厳密一致のまま残す分け方がある（本調査の本文に例は無い。推論）

代償:

  • 計算量: 読み書きのたびに候補の全体（または近傍）を見る。NRAM ではレジスタ1つが M 値の分布で、演算は分布どうしの演算になる
  • 行動の離散性: AutoCraftGame の I/O（移動・クラフト・転送）は離散で、分布のままでは世界へ出せない。出す段で離散化（最大の重みを取る）すれば、そこで跳びが戻る。標本化すれば1個体の表現型は「平均でしか連続でない」（登録 A3 の区別）
  • ①への影響: 人が書く番地は重み1の分布（一点）として書けるので、アセンブラで書く①は形の上では保てる。ただし、分布の番地を持つ語を人が意図して書く経路は、本調査の本文には無い

AL-15 のどちらの側に効くか

中間を作る側（C）。番地を指す記述が少し変わると、読み書きの対象が少しずれる。v9 で「ラベルの1bit 反転＝別の場所へ跳ぶ」だった編集が、「重みが少し別の場所へ漏れる」になる。

限界

  • 5 系のうち 4 系は①を満たさない学習系で、この手法を人が書くプログラムと同居させた例は ∂4 だけ。∂4 でも、分布の番地を持つのは学習で埋める穴の側である
  • 連続なのは緩和した意味論の中での連続で、世界へ出す行動は離散である（上の代償）
  • DNC は書誌のみで、本文は NTM で代えた
  • 移植の見込みは推論で、先方のコードを変えて試してはいない

手法 3: 命令の混合

主レポート: main.md。判定の根拠は raw/coding.jsonl、手法の判定は raw/methods.jsonl。出典は末尾。

一行で言うと

各命令の位置に「どの命令か」を1つ書く代わりに命令の上の分布（重み）を置き、実行は各命令の結果の重みつきの混合にする。ユーザが v9 の課題として挙げた「1bit の差で全く異なる命令になり、中間の命令も無い」に正面から当たる手法で、TerpreT（FMGD 後端）・∂4・NRAM の 3 系に現れた。中間の命令は、命令の集合の上の凸結合として作られている。代償は、状態（レジスタ・メモリ）も分布で持つ必要があることと、世界へ出す行動を離散に戻す段で跳びが戻ることである。

手法の定義（原典から）

TerpreT は、どの実行模型も勾配で解けるように緩和でき、そのとき微分可能な解釈器として見られると書く。

thus any TerpreT model can be viewed as a differentiable interpreter [Q-S11-1]

その後端 FMGD（周辺分布を前向きに計算し勾配で解く）は、NRAM の方式を一般化したものとして定義されている。

A gradient descent based approach which generalizes the approach used by Kurach et al. 2015. [Q-S11-2]

NRAM では、制御器が各時刻に「ぼやけた回路」を出力する——どのモジュール（演算）をどの入力に掛けるかが softmax の重みで与えられる。

The controller outputs the description of a “fuzzy circuit” with inputs [Q-B1-2]

どの処理系に現れ、どう判定されたか

処理系R1R2subcode分布で持つもの人が書く部分
TerpreT（S11）部分的部分的C穴の中の選択（命令・値）実行模型（どんな機械か）
∂4（S11b）部分的部分的C穴（slot）の振る舞いForth の下書き
NRAM（B1）満たさない満たすC各時刻のモジュールの選択なし（制御器を学習）

M1 は TerpreT・∂4（①部分的）で満たした。どちらも人が書く離散の部分（J）と、分布で持つ穴（C）を一つの処理系の中で分けている（登録の P2 が「層を分ける」と呼んだ型）。

AutoCraftGame v9 のどこへ移すか（A6）と代償（A5）

  • MemoryCore: 命令語に opcode の重みの列を持たせる（例: 語ごとに上位 k 個の命令と重み）。人が書く命令は重み1の一点として書ける
  • Processor: 算術・論理の命令（ADD/SUB/AND/OR/SHL…）は、各命令の結果の重みつき平均を書き込み先へ入れれば混合できる。レジスタの値を実数（または NRAM のように分布）で持つ必要がある
  • 混合できない命令: 分岐・ジャンプ（制御の流れ）と I/O（移動・クラフト・転送など世界への作用）は、結果を平均できない。手法 2（番地の分布化）と組み合わせて制御の流れを重みつきで持つか、ここだけ離散化・標本化する

代償:

  • 計算量: 1命令の実行が候補の命令の数だけの計算になる（符号化者の推論）
  • 行動の離散性: 世界へ出す段で最大の重みを取れば、重みがつり合う点で行動が跳ぶ。標本化すれば1個体の表現型は「平均でしか連続でない」（A3）。AutoCraftGame の個体は1回しか生きないので、この区別は効く
  • 状態の連続化: 算術の混合はレジスタの値を実数にする。v9 の 16bit 整数の意味論（物体 ID・材料の個数）とは合わない値が出る。整数へ丸める段で、また跳びが戻る

AL-15 のどちらの側に効くか

中間を作る側（C）。ADD と SUB の重みを少し動かすと、書き込まれる値が少し動く。変異が「ADD→SUB」の跳びではなく「ADD の重み 0.9→0.8」の一歩になる。

ただし、中間が意味を持つのは算術のように結果を平均して意味のある命令どうしに限られる。v9 の命令のうち、ロード・ストア・分岐・I/O・CHECKPOINT は平均の意味がはっきりしない。

限界

  • 本調査で到達した 3 系は、すべて学習（勾配）で分布を決める系で、変異で分布を動かす系ではない。「重みを変異で一歩ずつ動かすと表現型が連続に動く」ことは写像の定義から言える（C1）が、進化の中で使った例は母集団に無い
  • 上限の外に落ちた系に、微分可能な関数型プログラムの解釈器（N08）・神経的に解釈される言語（N09）など、この手法の近縁がある（本文は読んでいない。main.md の上限の節）
  • 連続なのは緩和した意味論の中での連続で、世界へ出す行動は離散である
  • 移植の見込みは推論で、先方のコードを変えて試してはいない
