何をやったか

題材

原典 SRC1 の再実装である。コードは公開されていないので、式からの自作であり原典の再現ではない（criteria.json の sourceFidelity）。

1次元の鎖に N=100 個体を並べ、各個体が角度 θ_i(t) を持つ。慣性 χ=1・線形弾性 k=20・3次の非線形 α=1e5・摩擦 γ=0.7 の「反応」項に、大きさ τ^A = k·δ_A の「能動」項を重ねる。能動項は左右で符号が違うので、左隣からの実効結合は k(1+δ_A)、右隣からは k(1−δ_A) になる——これが非相反性であり、作用と反作用が割れる。個体 1 だけは外から θ を与えられる駆動端で、全員 θ_I = π/2 から出発し、個体 1 だけが θ_1 = ω_0 t + π/2 で回って θ_FT = π に固定される。積分上限は原典の t̃_F = 31.3（実際の群れの U ターン 7 秒に対応）、刻み dt = 0.001 s で 6,998 ステップ。

主張の向きは事前登録に明記されている: δ_A を上げて c̄̃ が増え・η₃₅ が増えるなら支持、減るなら積極的に否定。

観測器（S-09 から定義を変えずに借りた6本 + 本スケッチ固有の6本）

S-09（2次元トーラス上の Reynolds 3規則 boid・主題は群れの中の情報伝播）の観測器6本——frontSpeed・reachedFraction（eps=0）・frontCorrelation・spreadCount・lyapunov・alignmentOrder——を、定義を一字も変えずにこの別の模型へ当てた。これが S-50 の選定根拠②そのものである。固有の6本は frontSpeedPaper（原典の瞬時速度平均 c̄̃）・efficiency35（原典の式(4) を i=35 で）・efficiencyProfile・reachedFraction2pct・dispersionAngle・nonreciprocityAudit。

母集団は i = 2..N（99 体）。駆動端 i=1 は受信者ではないので全集計から外す（登録済み。populationSize は全腕で 99 と記録されている）。

妥当性検査の結果

node apps/alife-sketches/s53-nonreciprocal-turning/selftest.js を本レポート執筆時に実行し、全項目通過を確認した。走行側の正コントロールは summary.json の positiveControls:

  • PC1（分散関係）: 6モードすべてで理論値 ω(q) = 2√(k/χ)|sin(qh/2)| と一致、最大相対誤差 1.31e-5（許容 1%）。長波長端の位相速度は 1 個体/t̃。実装ごと間違っている場合を捕まえる検査（K-18）が通っている
  • PC3（式(2) = 式(3)）: τ^A を陽に持つ形と k(1±δ_A) にまとめた形が θ_i(t̃_F) で 最大差 2.398e-14。δ_A の入れ方の符号ミスは無い
  • PC4（保存量）: γ=0 で δ_A=0 のとき H の相対変化 1.03e-10（< 1e-6 を要求）、δ_A=0.3 のとき 1.08e+2（> 1e-3 を要求）。非相反性は実装に本当に入っている（K-17 型の「壊したつもりで壊れていない」は起きていない）
  • PC2（数値光円錐）: 登録した検査とは別の、弱い検査が走っている。詳細は次節の食い違い②

PC2 の弱化に加えて、走行側の「正コントロール全通過」の判定そのものが登録と違う: 登録の decisionRule は「正コントロール4つを全て通すこと。1つでも落ちたら判定を行わず S2 へ差し戻す」と書くが、run.js:285 の positiveControlsPass は PC1・PC3・PC4 の3つだけで組まれており、PC2 は計算・表示されるが判定には入っていない。あわせて PC3 の許容は登録・run.log とも「1e-12」だが、コードは pc3MaxDiff < 1e-9 を見ている（実測 2.4e-14 なのでどちらでも通る）。

結果（事前登録した解析）

① 10腕がすべて走ったか — 走った

replicates.jsonl は 50 行 = 10腕 × 5シードで、A1〜A10 のすべてに 5 行ある（S-49 は腕が1つ走らず予測表にマスの空白ができていた。本スケッチではそれは起きていない）。予測表 50 マスに空白は無い。

シードの効き方は事前予告どおりだった: A1〜A9 は 5 シードの stateHash が完全に一致（各腕で相異なるハッシュが1つだけ）、A10 だけ 5 シードすべて異なる。登録の whatSeedChanges は「主要8腕ではシードは1ビットも変えない」と事前に予告しており（S-23 は同じことを事後に発見した／K-47）、実測がそれを確認した。したがって本レポートは「5シード」を統計的な裏付けとして書かない。

② 主判定 — 機械判定は「支持する」。その内訳を開く

summary.json の decisionRule は次のとおり:

{ "monotonic": true, "speedRatio": null, "magnitudeOk": true,
  "directionOk": true, "positiveControlsPass": true, "verdict": "支持する" }

主判定の 4 腕（ω̃0 = 0.0581、実験条件）と向きの検査 A7 の実測:

登録の支持条件は3つである。順に実測と突き合わせる。

(1) 単調性 — c̄̃ が 0 ≤ 0 ≤ 2.359 ≤ 3.708、η₃₅ が 0.341 ≤ 0.471 ≤ 0.624 ≤ 0.791 で、いずれも単調非減少。成立する。 ただし c̄̃ の前半2つの「≤」は 0 = 0 の同点であり、単調性の証拠を提供しているのは実質 A3・A4 の2点だけである。

(2) 大きさ — 登録は 「c̄̃(0.3)/c̄̃(0) ≥ 10 かつ η₃₅(0.3) − η₃₅(0) ≥ 0.3」。後半は 0.791 − 0.341 = 0.450 ≥ 0.3 で実測が通す。前半は 分母が 0 なので比が定義できない。run.js:284 は

const magnitudeOk = (cbar('A1') === 0 ? cbar('A4') > 0 : speedRatio >= 10) && (eta('A4') - eta('A1') >= 0.3);

と書かれており、分母が 0 のときは「c̄̃(0.3) > 0 でありさえすればよい」という代替規則へ切り替わる。この代替規則は criteria.json に登録されていない。 run.log はこれを「大きさ(比=∞, Δη=0.450)=true」と印字し、summary.json は speedRatio: null を残している（JSON が Infinity を持てないため）。「比 = ∞」は測定ではなく、0 除算を分岐で避けた結果の表示である。 登録した閾値 10 は、この走行では一度も評価されていない。

(3) 向きの検査 — 登録は「A7 が A1 より遅く・効率が低い」。効率は 0.104 < 0.341 で明確に成立する。速度は cbar('A7') < cbar('A1') + 1e-9 すなわち 0 < 1e-9 で、打ち切り値どうしの同点比較が通っている。

まとめると、6つの下位条件のうち実測の数値が決めたのは η₃₅ 由来の3つ（単調性の効率側・大きさの効率側・向きの効率側）であり、c̄̃ 由来の3つはいずれも「到達個体が5未満だから推定量を出さない」という登録済みの規約が返した 0 どうしの比較だった。これは欠陥の指摘ではない——規約そのものは事前登録されており、reachedCount2pct も生ログに残っている。報告すべき事実は、判定の名目上の根拠が2本（速度と効率）であるのに、実際に判別していたのは1本だったことである。

③ 「定義上そうなる」と宣言した量が、実測では最も綺麗に δ_A へ依存した

登録は reachedFraction（eps=0、S-09 から借りた量）について、複数箇所で同じことを断言している——「定義上そうなる: 半陰的 Euler は1ステップで隣接のみを結び、6,998 ステップは 99 個体へ届くのに十分。δ_A にも力学にも依らない」「Rr は δ_A について判別力をゼロしか持たず、支持の根拠に使ってはならない」。forcedCellAudit は Rr の全10マスを forced に数えている。

実測（replicates.jsonl、5シードすべてで同一）:

5点すべてで単調に増加し、A7 → A4 で 1.71 倍になる。 1.0 に張り付く腕は A5・A6（高角速度）と A10（無作為結線）だけである。

S2 の申し送り②はこれを「float64 の ULP 効果であって欠陥ではない。因果律の上限は破られていない」と申告した。本レポートは独立に再現し、定量した（core.js を読み込んで直接走らせた。S2 の出力には依存していない）:

  • 到達集合はどの δ_A でも {個体 2 … 個体 m} という切れ目のない前置区間であり、途中に穴は無い。光円錐違反（i 番目が i ステップより早く到達）はどの腕にも 1 件も無い
  • 検出の打ち切り位置 m のすぐ内側で |θ_i − θ_I| は 3.5e-15 〜 1.8e-13、その外側では 厳密に 0.0。float64 の π/2 における ULP は 1.74e-16
  • 前駆波の空間減衰を ln|θ_i − θ_I| の i に対する直線当てはめで取り、ULP と交わる位置を予測すると 53.2 / 64.7 / 70.7 / 78.4 / 87.7（δ_A = −0.3 / 0 / 0.1 / 0.2 / 0.3）。実測の打ち切り位置は 51 / 63 / 69 / 77 / 87。予測と実測が 2 個体以内で一致する

すなわち reachedFraction（eps=0）が測っていたのは光円錐の広がりではなく、「擾乱の指数的な裾が 1 ラジアンの 1e-16 を下回るのはどこか」 である。その位置は δ_A とともに外へ動く。登録が判別力ゼロと宣言した量は、実際には δ_A の単調な関数だった——ただしその絶対値を決めているのは物理ではなく計算機の仮数部の長さなので、この量を主張の支持に使うことは依然できない。「判別力が無い」という宣言は外れ、「支持の根拠に使うな」という結論は（別の理由で）正しかった。

これは正コントロール PC2 の前提そのものでもある。 親からの申し送りは「PC2 は δ_A に依らないことが期待される。依存が出ていたら実装を疑うこと（K-18）」だった。実測は 依存が出ている。しかし実装を疑う先は核ではない——因果律の上限（PC2 の neverFaster）は δ_A に依らず厳密に守られており、依存が出たのは「上限」ではなく「検出できた範囲」のほうである。登録が両者を同じ1つの量で書いていたことが、この取り違えの原因である。

④ 正コントロール PC2 は、登録した形では通らない形に書き換わっている

登録した PC2 は 「eps=0 到達集合は n ステップ後に厳密に {1,…,n+1} と一致するはず。一致しなければ検出器か核が壊れている」。実装（run.js:243-246・selftest.js:81-86）が検査しているのは2つだけである:

if (pc2Run.arrivalEps0[i] >= 0 && pc2Run.arrivalEps0[i] < i + 1) pc2NeverFaster = false;  // 上限を破らない
if (i <= 2 && pc2Run.arrivalEps0[i] !== i + 1) pc2ExactNear = false;                      // 近接2個体だけ厳密

selftest.js の出力が実際の到達ステップ列を印字している（N=16・t̃_F=3）:

arrivalEps0 = -1, 2, 3, 6, 22, 52, 97, 155, 225, 303, 390, 483, 581, -1, -1, -1

厳密一致は i=1,2（到達 2, 3 ステップ）までで、3番目の個体はすでに光円錐の 4 ステップに対し 6 ステップ、12番目では 13 に対し 581 ステップ、13〜15番目は最後まで検出されない。 登録どおりの「厳密に {1,…,n+1}」を検査していれば、PC2 は3番目の個体で落ちていた。

これは「弱い検査に差し替えられた」という一事実として報告する。差し替え自体が不当だとは言えない——③のとおり、ずれの原因は核でも検出器でもなく浮動小数点の表現限界であり、登録の PC2 は達成不能な検査だった（K-53 の「答えが決まってしまう」の裏返しで、こちらは「定義上通れない」）。報告すべきは、登録した検査は走っていないという事実と、登録の「1つでも落ちたら S2 へ差し戻す」という規律が、落ちうる1本を判定から外すことで維持されているという構造である。

⑤ 予測表 50 マスの的中 — forced のほうが当たっていない

登録は「50 マス中 18 マスが forced（定義上そうなる）」と自己申告し、内訳を Rr の全10マス・A8 の全5マス・A9 の全5マス（Rr 重複）としている。S-49 は 18 マス中 7 マスが自明で実質の証拠は 8 マスしか無かったという前例があるので、ここは分けて数える。

「定義上そうなる」と申告したマスのほうが、そうでないマスより当たっていない。

forced の 5 件の外れはすべて同じ規則・同じ位相である: Rr × {A1, A2, A3, A4, A7}（＝鎖トポロジーの全5腕）。いずれも「1.0 になる」と予告して 0.515〜0.879 が出た。③のとおり原因は ULP であり、forced の申告が「物理の定義」ではなく「無限精度算術での定義」を指していたことによる。A8・A9 の 8 マス（駆動を切る／伝達路を切る）は8 マスすべて的中しており、こちらの forced は正しく forced だった。

forced でない 8 件の外れの内訳も、向きを持っている:

  • 3 件は「到達個体 5 未満なら偽」という登録済みの規約が返した（A1/Rf・A2/Rc・A2/Rf）。値が低かったのではなく、値を計算していない
  • 3 件は閾値の 1〜4% 以内で決まった（A4/Re 0.7914 対 0.8 ／ A5/Rf 0.2979 対 0.30 ／ A10/Ra 0.9156 対 0.95）
  • 2 件は大きく外れた（A3/Re 0.624 対 0.8 ／ A10/Re 0.165 対 0.8）

登録は判別力の弱いマスを4つ事前に名指ししていた（A2/Rc・A3/Re・A1/Ra・A10/Ra）。そのうち 3 つが外れ（的中 1/4 = 25%）、名指ししなかった 28 マスは 21/28 = 75%。登録の自己診断はよく当たっている。 ただし A4/Re と A5/Rf は「閾値の 1% 以内で決まった」にもかかわらず事前に名指しされていない——名指しの規則は「予測値が閾値の近傍」であって、実測値が近傍に来るかは事前には分からない、という限界がここに出ている。

主判定に直接効くのは A4/Re である。 η₃₅(A4) = 0.7914 は閾値 0.8 を 0.0086 下回っている。後述の N 掃引では N=50 で 0.8256 となり Re は真へ反転する。

noiseFloor の事前見積もりは実測を 100 倍以上外している。 登録は「η 換算 0.031」と見積もり、「見積もりが実測を 2 倍以上外していたら判定の許容を見直す必要があるので S4 へ申し送る」と書いていた。実測の数値誤差は θ の最大差で 1.98e-4（刻み半分）・3.83e-4 rad（RK4）、η 換算で 1.26e-4 / 2.44e-4 である。見積もりは実測の約 127 倍にあたる。申し送り事項として記録する。 影響は2つに割れる:

  • 一方、A4/Re の 0.0086 という閾値からの距離は、床の 35 倍である。「A4 の Re が偽なのは数値誤差のせいではない」と言える——これは実測の床が分かって初めて言えることであり、登録の見積もり 0.031 を使うと 0.0086 は床の内側に入ってしまい「判定できない」になっていた

⑨ 上限 5 件 — 落とした集合そのものを見る（K-26・K-63）

C1（t̃_F = 31.3 / censored-boids.json / 759 件）。腕ごとの打ち切り数は A1 98・A2 97・A3 88・A4 82・A7 99・A8 99・A9 99・A10 97（A5・A6 は 0）。各腕で「打ち切り + 到達 = 99」が成り立っており、登録した分母（i=2..N の 99 体）と記録側の分母は一致している（S-52 では 256/2 と 256/4 の食い違いがあったが、ここでは起きていない）。ただし ファイル内の添字 i は 0 始まりで、登録が語る「個体番号」（1 始まり）と 1 ずれている（A4 の最小 i は 18、これは boid 19 であり、boid 2〜18 の 17 体が到達したことと整合する）。

上限に事例が張り付いている（K-26）。 2 つの形で張り付いている:

  • 到達時刻が全部、窓の終端に寄っている。2% 到達が起きるのは A4 で t̃ = 26.75 〜 31.06、A3 で 26.90 〜 31.14。t̃_F = 31.3 の窓のうち、最後の 14% にすべての到達事象が入っている。 最後の到達は上限の 0.8% 内側である。窓を延ばせば到達は増え続ける——size-sweep の A4 は N=50 で到達 17 体、N=100 で 17 体、N=200 で 17 体と個体数では飽和しているが、これは空間の飽和であって時間の飽和ではない
  • 打ち切られた個体は「届いていない」わけではない。A4 で打ち切られた 82 体のうち 36 体は η > 0.5、8 体は η > 0.9、最大は 0.979。2% 到達の帯は |θ_i − π| ≤ 0.0314 rad すなわち η ≥ 0.98 なので、η = 0.979 の個体が「未到達」に数えられる。reachedFraction2pct は「情報が届いたか」ではなく「θ_FT まで回り切ったか」を測っており、c̄̃ はその『回り切りの前線』の速度である

この2つが合わさると、②で見た c̄̃ の振る舞いが説明できる。 駆動端 i=1 が転回を終えるのは t̃ = π/(2ω_0) = 27.0（登録の controlTimescale が事前に「観測窓の終端は駆動端がようやく転回を終えた直後にあたる」と明記していた）。到達事象はその直後の 4.3 t̃ に全部入っている。 c̄̃ = 3.708 はその 4.3 t̃ 幅の窓での局所的な傾きであって、原点から測った通過速度ではない——個体 18 が t̃ = 31.06 に到達しているので、原点からの平均速度は 17/31.06 = 0.547 個体/t̃ にすぎない。登録が事前に承知した重なりが、そのまま速度推定の性質を決めている。

C2（掃引格子 / sweep-grid.json）。掃引したのは δ_A ∈ {−0.3, 0, 0.1, 0.2, 0.3} × ω̃0 ∈ {0.0581, 1.118, 44.72, 223.6}。最大の効果は掃引した δ_A の上端（0.3）で出ている——上限に張り付いている。原典本文は δ_A = [0,1] と書くので、登録した定義域の 70% は見ていない。ω̃0 は 4 値のみで、原典が「境界層がある」と書く 10 前後は見ていない。ω̃0 = 1.118 と 44.72 は格子には登録されているが、10 腕のどれもこの2値を使っていない（A1〜A4・A7 が 0.0581、A5・A6 が 223.6）——格子に書かれた 20 点のうち実際に走ったのは 10 点である。

C3（数値発散 / diverged-runs.json）は空である。 entries: []、divergedRunsCount: 0。空であることの意味を書く: 打ち切り条件は |θ_i| > 4π または |dθ_i/dt| > 1000 rad/s である。本系の θ は駆動端が θ_FT = π で固定され、他の個体はそれを追う——実測の最大分散角（dispersionAngle）は 0.605 rad で、θ が 4π = 12.57 に届く経路が力学に無い。したがってこの空は「硬い3次項（α=1e5）にもかかわらず系が安定だった」という主張ではなく、「上限が力学の到達しない場所に置かれていた」という事実である。 登録の意図（発散を『現象が無い』と報告しないため）は正しいが、この配置ではこの上限は一度も噛んでいない。より噛む上限（たとえば |θ − θ_I| が θ*_FT を大きく超える「行き過ぎ」の監視）は登録されていない——実際、η の生値は最大 0.979 で 1 を超えておらず、sourceFidelity が心配した「η > 1 の行き過ぎ」は本走行では観測されていない。

⑪ S-09 の観測器を別の模型へ当てた結果（RP6・S-50 の選定根拠の検証）

S-50 が S-53 を1位に置いた根拠②は「S-09 の観測器6本が定義を変えずに全部当たる——再実装が最も安い」だった。実測は、字面では支持し、内容では条件付きで支持する。

  • δ_A について 5 点すべてで単調だったのは4本——efficiency35（本模型固有）・reachedFraction・spreadCount・dispersionAngle。そのうち判定規則に入っているのは efficiency35 だけである。判定に使った frontSpeed は 5 点中 3 点で値を持たず、判定に使わないと宣言した reachedFraction と、規則に入れなかった spreadCount が 5 点とも値を持って単調だった
  • S-09 が「群れらしさと情報伝播は別物」を示すのに外部方向場を要したのに対し、本模型では結合定数を落とすだけで同じ系（A9）が作れた。登録の予告どおりである

事後解析（事前登録していない）

以下は登録に無い。結果を見てから行った。判定には一切使わない。

(a) ULP 仮説の独立検証。 ③に書いた再走行・減衰率の当てはめ・ULP 交点の予測は、本レポートの書き手が core.js を直接呼んで行ったものであり、事前登録にも S2 の出力にも無い。S2 の申し送り②を鵜呑みにせずに確かめるために行った。

(b) 原点からの通過速度。 ⑨と⑪で使った「最後の到達個体番号 ÷ その到達時刻」は登録された推定量ではない。登録は回帰の傾きと瞬時速度平均の2通りだけを登録している。この第3の読みで測ると、登録の大きさの条件（比 ≥ 10）が定義可能になる: 0.547 / 0.037 = 14.8 ≥ 10 で通る。したがって「登録の閾値 10 は評価されなかった」（②）は、推定量を変えれば評価できたし、通っていたと言える。ただしこれは結果を見てから選んだ推定量である。

(c) 超音速の機構。 c̄̃ = 2.36〜3.71 は登録した線形音速の帰無値 1 個体/t̃ の 2.4〜3.7 倍である。3次項による実効剛性 k_eff = k + 3α(Δθ)² に隣接角差 Δθ ≈ 0.02 rad を入れると k_eff ≈ 140 で、速度比 √(k_eff/k) ≈ 2.65。非線形硬化だけで 2.65 倍が説明でき、残りが非相反性のポンプに当たると読める。RP5 の α=0・δ_A=0.3 が c̄̃ = 2.40 を出していることと整合する。PC2 の光円錐（1 個体/step = 223.6 個体/t̃）は破っていないので、因果律の問題は無い。

(d) 高角速度の腕で推定量が割れる。 A5 で回帰の傾き 6.563 対 瞬時速度平均 29.198（4.4 倍）、A6 で 21.89 対 31.87（1.46 倍）。低角速度の A3・A4 では両者が 0.1% 以内で一致する。登録は「原典が波面の加速を報告しているので両者は一致しないはず」と予告したが、実測では低角速度で一致し、高角速度で割れた——予告の向きは半分だけ当たっている。A5・A6 では 99 体全員がほぼ同時に到達するので到達時刻の順序が細部に支配され、frontCorrelation も 0.298 / 0.408 と鎖の A3・A4（0.99999）より大きく低い。最も速い腕が最も波面らしくないという逆転が出ている。

(e) 原典の分岐 (i) は、僅差で triggered しなかった。 登録は「高角速度で δ_A の差が消えなければ原典の主張が否定される」「原典どおりなら A5 と A6 の η₃₅ の差は 0.1 未満」と書いた。実測の差は 0.99992 − 0.90359 = 0.0963 で、0.1 を 0.0037 下回って条件を満たす。c̄̃ のほうは 29.198 対 31.868 で 9.1% 差が残っている。分岐の判定が 0.0037 で決まっていることは記録しておく。

本家サブプロジェクトへの含意（候補として挙げるだけ。要件化しない）

  1. 「作用と反作用を割ると情報が速く伝わる」は、本再実装では効率の側で明瞭に再現された（0.341 → 0.791、原典の差 0.50 に対し 0.450）。速度の側は、観測窓と駆動の所要時間が重なる配置では推定量が窓の端の局所傾きになり、実装ごとに桁が動きうる。
  2. 非相反性は慣性を必要とし、非線形を必要としない（RP5）。過減衰（Vicsek 型）にすると δ_A があっても何も伝わらない。非線形は非相反性の効果を 1.3 倍に増幅するが、非相反性なしでは（波面という意味では）何も生まない。
  3. 「短い経路」と「向きの一貫性」は別の性質である（A10）。無作為2-正則結線はグラフ直径を縮めて eps=0 到達を 1.0 にするが、δ_A の非相反性が鎖の上で担っていた方向を持ったポンプが経路上で打ち消し合い、効率はむしろ下がる。非相反な結合の効果はネットワークの向き付けに依存する。
  4. 「整列していること」は「情報が伝わること」の証拠にならない——S-09 が2次元 boid で示したことが、1次元の非相反スピン鎖でも、別の壊し方2通り（駆動を切る／結合を切る）で再現された。しかも本模型では結合定数を落とすだけでその系が作れる。

  • 原典のコードは公開されていない。本実装は式からの自作であり、原典の再現ではない。 数値が一致しなくてもどちらが正しいかは決められない
  • 原典が書いていないものが本実装で決め打ちになっている: 境界条件（自由端を既定。RP7 で固定端も走らせ、N=100 では 16 桁一致だった）／積分法（半陰的 Euler。RK4 との差は最大 3.83e-4 rad）／h（本文に無い。§V の桁数評価から h³ = 0.10 と逆算したが、式(3) に h は現れないので主結果には入っていない）／v₀（実装していない。θ の力学に一方向に従属し、どの観測器も個体の位置を使わないため。S2 申し送り⑤）
  • 原典の誤りを3件、S1 が特定して読み替えている: ω̃0 = 224.6 → 223.6、効率の式の誤植（本文どおりの読みは η ≡ 1 を返すことを実測で確認）、h の未記載。読み替えが正しいという保証は原典の中には無い

  • 書誌の版が割れている。 本スケッチが読んだのは ar5iv 版・本文日付 2026-08-10、S-50 の arXiv API 層は published 2026-04-26。同じ arXiv id の中で層によって「正」が違う（K-99）

  • ω̃0 は実質 2 値しか使っていない。 格子には 4 値が登録されているが、10 腕は 0.0581 と 223.6 しか使っておらず、原典が「境界層がある」と書く ω̃0 ≈ 10 の前後は見ていない
  • 観測窓 t̃_F = 31.3 と駆動の所要時間 π/(2ω_0) = 27.0 が重なっている（登録が事前に承知している）。2% 到達事象は窓の最後の 14% に全部入るので、「まだ届いていない」と「永久に届かない」は本スケッチでは区別できない。c̄̃ はその 4.3 t̃ 幅の窓での局所的な傾きである
  • 主判定の一方（c̄̃）は、δ_A の 5 点中 3 点で値を持たない。 登録した大きさの閾値 10 はこの走行では一度も評価されていない（代替規則が走った）

  • A10 の Re は 5 シードで 0.165 / 0.832 / 0.193 / 0.210 / 0.544 とばらつき、シード 2 だけ閾値を超える。 summary.json と run.log はシード 1 だけを腕の代表として印字している
  • 主要 8 腕は決定論的で、5 シードは統計的な裏付けを与えない（ハッシュが全一致）。ばらつきに意味があるのは A10 と頑健性の腕だけである
  • S-09 との桁の並置は等価な単位の比較ではない（登録が明記）。S-09 の 1 step は個体の反応時間、S-53 の 1 t̃ は弾性の固有時間 √(χ/k) = 0.2236 s である

  • 上限 3 本（発散の打ち切り・結線の引き直し 100 回・N ≤ 200）はこの配置で一度も噛んでいない。 それぞれ「安定だった」「結線が引きやすかった」「N が足りた」という積極的な主張ではなく、上限が力学の届かない位置に置かれていたという事実である
