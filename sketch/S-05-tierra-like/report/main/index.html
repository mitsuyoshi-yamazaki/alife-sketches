出典（アイデアのみ。コードは参照せず、命令集合も祖先プログラムも自分で設計した）: Thomas S. Ray (1991) "An Approach to the Synthesis of Life", *Artificial Life II*, SFI Studies in the Sciences of Complexity, pp. 371-408。 照合には著者自身の別稿 "Evolution, Ecology and Optimization of Digital Organisms" を使った（PDF）。

一行で言うと

誰も設計していない「他人の複写手続きを借りて増える個体」が出た。しかもそれは祖先から遠くない—— 祖先の1点変異 1829 通りのうち 291 通り（15.9%）がその場で借用体になり、うち 132 通りは複写命令を 1回残らず自分の外から取ってくる。 複写の誤り率を 0 から 0.03 まで上げると、系全体で 「自分のブロックの外から取得された複写命令の割合」は 0 → 0.013 → 0.026 → 0.038 → 0.056 → 0.079 → 0.180 と 単調に上がり、事前登録した閾値 0.05 を最初に超えるのは誤り率 0.003 だった。 誤り率 0 の系ではこの量は厳密に 0 を返す——半径も窓幅も選んでいないので、これは実測ではなく定義から従う。

何をやったか

題材

共有メモリ（環状のバイト配列）の上で、機械語プログラムが自分を複製する。Tierra の肝は テンプレート照合による番地指定にある。絶対番地を持たず、探索命令の直後に並ぶ nop0/nop1 の列 （テンプレート）の補完パターンをメモリから近い順に探して、そこへ飛ぶ・そこを指す。

call  nop0 nop1 nop1 nop0     ← テンプレート 0110
                              ← 補完 1001 の並びを近い順に探し、その直後へ飛ぶ

絶対番地なら1命令ずれただけで壊れる自己参照が、この方式だと変異に対して頑健になる。 そして同時に、参照先が自分のコードである保証も無くなる——本報告の観測対象はここから出てくる。

祖先プログラム（59 命令、1複製あたり 375 命令）は自分で設計した。先頭と末尾に目印を置き、 後方探索で自分の先頭を、前方探索で自分の末尾を見つけ、差を取って全長を知り、その長さぶん確保し、 複写手続きを call で呼び、split する。書いてみて最も嵌ったのは、テンプレートが 「直後に続く nop の極大列」であることで、テンプレートの隣に目印を置くと1本に繋がって照合が壊れる。 境目に実行されない区切り命令を挟んで解決した。

核の側には「生物」「寄生」「宿主」「適応度」という語も概念も無い。 あるのはメモリ・プロセス・ 確保記録・命令語・待ち行列だけである。

観測器: スケールの自由度を持たない量を主に据えた（K-10 の実地）

K-10 は「スケールの選択を含まず、理論的な帰無値を持つ量を主にせよ」と言う。 S-02 では事後に気付いた形だったので、今回は実装より先に据えた。

主の秩序変数副
定義集計窓の間に実行された複写命令 mov_ii のうち、その命令の取得アドレスが実行主体のブロックの外にあったものの割合生存プロセスのうち、自分のブロックに mov_ii を1つも含まないものの割合
スケールの自由度無い。「自分のブロック」は仮想機械が持つ確保記録そのもの（start..start+len）であり、半径も閾値も窓幅も選んでいない無い。同上。mov_ii はメモリに書き込む唯一の命令語
帰無値厳密に 0（どのプロセスも自分のコードだけを実行する系では定義から 0）厳密に 0
閾値0.050.05

残る自由度は集計の時間窓だけで、これは「走行の最後の 25%」として事前登録した。 「寄生体」という上位概念は観測器の側にも置いていない——測っているのは 命令の取得アドレスが確保記録の外にあったかという、機械が既に持っている事実だけである。

妥当性検査が、本番前に仮想機械の欠陥を5つ捕まえた

node selftest.js（26 項目）。5つとも本番を1回も走らせる前に出た（K-2）。 うち4つは「増え方の抜け道」で、いずれも正しいパスだけ動かしていては絶対に気付けない:

出方中身対処
誤り率 0.001 で系が絶滅した大きな確保が1命令あたり最大 16 体の取り除きを誘発していた空きが無いときの取り除きを1回の確保あたり 2 体までに制限
1体が 89,523 回分裂し、中身の無い娘でメモリを埋めた解放したメモリを消していなかったので、1命令だけ書いて split すれば前の住人のコードがそのまま手に入った確保した領域を 0 で埋める（calloc と同じ約束事）
1セルだけ確保して分裂するのが最速になった確保の大きさに下限が無かった確保は自分の長さの 1/3〜3 倍に限る
split が 1 命令書いただけで通った充填の条件が無かった領域の長さぶん書き込まれるまで独立させない
生存一覧に取り除き済みのプロセスが残り、観測器がそれを1個体として数えていた巡回中に「既に通り過ぎた添字」のプロセスが取り除かれると詰め直しが走らなかった取り除きに印を立て、巡回の終わりに必ず詰め直す

最後の1つは S-02 の「格子の陳腐化」と同じ形（逐次更新した索引が実体から離れる）で、 逐次更新している表を、一覧から作り直したものと突き合わせる検査が拾った。

正コントロール（手で書いた複写手続きなしプログラムを祖先の隣に注入）では、主の秩序変数 0.366・ 副 0.444 と強く反応し、注入したプログラムは 40 万命令で 116 体まで増えた。 負コントロール（誤り率 0）では両方とも厳密に 0、系統は1つだけ、長さは 59 のまま動かなかった。

閾値 0.05 を最初に超えるのは誤り率 0.003。 レプリケート単位では 4/5 が超えた （0.0723 / 0.0436 / 0.0530 / 0.0615 / 0.0517）。その手前の 0.001 は 0/5（0.032〜0.042）で、 またぎは平均だけの産物ではない。

K-6 により、そこで出たものの規模を併記する: 誤り率 0.003 の時点で 「複写命令の過半を自分の外から取る個体」は 257 体中およそ 9 体（3.5%）、 「自分のブロックに複写命令を1つも持たない個体」は 1.8% にとどまる。 つまり閾値をまたいだ時点の借用は、系を占めてはおらず、少数派として常在している規模にあたる。 誤り率 0.03 まで上げると借用個体は 17%、複写命令なしは 12% になる。

副次的に出たもの（掃引の生ログに残っている）:

  • 長さが縮む。祖先 59 から中央値 56〜57 へ。誤り率 0.001 の時系列では 59 → 57（8M 命令）→ 56（44M 命令）と段階的に降りる。CPU の持ち分をブロック長に比例させてある（＝長さに中立）ので、これは実行速度ではなく空間の取り合いによる
  • 系統数が誤り率とともに単調に増える（1 → 32 → 52 → 78 → 109 → 185 → 276）
  • 誤り率 0.03 でも個体数は減らない（むしろ 308）。長さが縮むぶん多く入る

事後解析（事前登録していない）

掃引の結果を見てから足した。祖先から借用体までの距離を知りたくなったので、 祖先の1命令だけを変えた全変異体 59 箇所 × 31 通り = 1829 体を1体ずつ作り、無傷の祖先の隣に置いて 短時間走らせ、行き先を機械的に数えた（node posthoc.js）。

行き先数割合
自分で複製する109559.9%
外から複写命令を取って複製する29115.9%
複製しない44324.2%

うち 132 通りは、複写命令を1回残らず自分の外から取る（外部取得率 1.0）。 どこを変えるとそうなるかもはっきりしている:

位置 39,40,41,42（複写手続きの見出し 1001）… 31/31 通りすべてが借用体になる
位置 4,5,6,7    （繰り返しの戻り先 0101）  … 27〜29/31
位置 50         （見出しを探すテンプレート）… 26/31

理由は機構から一意に説明できる: 見出し 1001 が1命令でも壊れると、call の探索が自分の体内で 一致を見つけられず、そのまま隣のプロセスの見出しまで伸びる。借りた先の複写ループは 借用体自身のレジスタで回るので、複写されるのは借用体自身の中身である。つまり 「寄生」は追加の発明ではなく、テンプレート照合という番地指定の仕方から自動的に落ちてくる。

Ray の記述（上記2本目）とも一致する: *"0045aaa is a 'metabolic parasite'. Its genome does not include the copy procedure, however it executes the copy procedure code of a normal host"*。

正コントロールでも同じ機構の帰結が見えた。手で書いた借用体を注入すると 25 万命令で 136 体まで増え、 その後150 万命令までに絶滅した。Ray も同じ密度依存を書いている—— *"When the hosts become scarce, most of the parasites are not within the search limit of a copy procedure, and are not able to reproduce. Their calls to the copy procedure fail and generate errors"*。 本実装では失敗した探索が不成立命令として数えられ、そのプロセスは取り除きの待ち行列を先頭側へ寄る。

最後の逸脱だけは結果に効く。消さないままだと「1命令だけ書いて split する」だけで前の住人のコードを 手に入れられ、実測では1体が 89,523 回分裂して系を埋めた。Tierra がこれを何で防いでいるかは 照合できた文書からは分からなかったので、機械の約束事として零詰めを入れた（criteria.json の machineRules に明記してある）。

本家サブプロジェクトへの含意（候補。要件化はしていない）

  • 「上位概念を核に持たせない」は、観測器にも同じ強さで効く。本スケッチでは「寄生体」を核にも観測器にも

置かず、「命令の取得アドレスが確保記録の外にあった」という機械が既に持つ事実だけを数えた。 結果として帰無値が理論から出る（0）。artificial-life の語彙分離は 仕様の側の規律として書かれているが、観測器の側にも同じ線を引けるかもしれないという候補

  • 基層が持つ「参照の仕方」が、どの生命的性質を可能にするかを決めているかもしれない。ここでは

寄生は追加の自由度ではなく、テンプレート照合という参照方式から 1 点変異の距離に置かれていた。 「どの自由度がどの性質を初めて可能にするか」を問うとき、自由度そのものより参照の仕方を見る価値がある

  • 以上はいずれも候補であり、採否はユーザが個別に判断する

限界（この実験が言えないこと）

  • 「寄生体が現れた」とは言っていない。言えるのは「複写命令を自分のブロックの外から取得して複製する

個体が、設計せずに現れ、少数派として常在した」まで。生態学的な役割（宿主への害・共進化・免疫）は 一切測っていない

  • 原典の忠実な再現ではない。上の照合表のとおり、祖先・探索距離・変異の作り方・取り除きの発火条件が

違う。1991 年の原典は画像スキャンで読めず、照合は著者の別稿で行った。命令集合の各命令の意味は 自分で決めたものであり、Tierra と同名の命令が同じ意味とは限らない

  • 走行が短い。1レプリケート 6000 万命令（祖先の複製 16 万回ぶん）。Ray の長い走行は 28.6 億命令で、

そこで初めて見えた現象（超寄生・社会性・punctuated equilibria）には本実験は届いていない
